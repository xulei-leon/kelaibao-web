# 客来宝政策页友好化与“合作与使用说明”内容重组设计

## 1. 背景与目标

当前 `/disclaimer` 以“免责声明”为标题，按职业资质、机构审核、直销、保险、证券和效果边界逐项展开。内容准确但连续使用防御性、否定式表达，容易让访问者在尚未建立信任前先感受到风险提示，削弱商业官网的亲和力与专业形象。

本次调整将页面重新定位为公开的品牌合作承诺：用真实、清晰、尊重授权和长期价值四项原则说明客来宝如何开展合作。页面不再承担逐行业列举职业资质、直销、保险和证券边界的职责，也不要求完整保留原有行业条款。

同时统一三个政策页及页脚入口的对外名称：

- `/privacy`：“隐私政策”改为“信息与隐私说明”；
- `/terms`：“服务条款”改为“合作服务说明”；
- `/disclaimer`：“免责声明”改为“合作与使用说明”。

三个 URL 保持不变。除 `/disclaimer` 的正文重组和公共页脚摘要调整外，`/privacy` 与 `/terms` 本次只修改页面名称、入口名称和对应 metadata，不改写其政策正文。

成功标准：

- 访问者首先感知客来宝的专业态度和合作诚意，而不是防御性免责。
- 页面仍能清楚说明内容真实性、双方责任、公开授权和成果预期。
- 三个政策页的可见标题、页脚入口和 metadata 使用统一、友好的名称口径。
- `/disclaimer` 的目录和正文使用同一套“合作与使用说明”口径。
- 不新增服务能力、结果承诺或未经确认的商业事实。

## 2. 页面定位

- 路由保持 `/disclaimer`，避免产生不必要的链接迁移和重定向工作。
- 页面可见标题由“免责声明”改为“合作与使用说明”。
- 页脚政策入口同步改名为“合作与使用说明”。
- 页面角色从“逐项免责清单”改为“品牌合作原则与使用边界”。
- 保留现有 `PolicyLayout` 和长文阅读样式，不进行无关视觉改版。

## 3. 信息架构

页面采用“引言 + 四项品牌承诺 + 合作邀请”的结构。

### 3.1 页面引言

目的：先解释这页为什么存在，并把边界表达转化为合作信任。

建议文案：

> 客来宝相信，持续有效的合作建立在真实、清晰和彼此信任之上。以下原则说明我们如何使用客户提供的信息、如何推进内容与服务，以及双方共同维护的合作基础。

### 3.2 承诺一：真实表达

目的：说明内容真实性原则，替代原页面按行业罗列的禁止表达。

建议文案：

> 我们以真实业务、真实经验和已经确认的材料为基础开展工作，不通过夸大、虚构或容易引起误解的表达制造吸引力。客户应确保提供的信息准确、合法，并与实际业务保持一致。

### 3.3 承诺二：清晰合作

目的：明确范围、交付和双方责任，减少合作预期偏差。

建议文案：

> 合作开始前，我们会共同确认目标、服务范围、交付方式和必要的配合事项；执行过程中保持沟通，并以双方确认的信息推进。客户负责其业务决策以及最终对外使用和发布的内容。

### 3.4 承诺三：尊重授权

目的：保留现有客户材料与公开授权要求，但改为积极承诺。

建议文案：

> 姓名、照片、评价、品牌标识、案例及合作信息，仅在来源清楚并获得适当授权后使用。我们尊重客户、合作伙伴及相关权利人的合法权益，不以虚构身份或未经许可的材料替代真实证明。

### 3.5 承诺四：重视长期价值

目的：以建设性方式说明成果受多种因素影响，避免空泛承诺。

建议文案：

> 我们关注持续拓客能力和可信品牌资产的积累，不以短期数字制造不切实际的预期。实际成果会受到业务基础、投入程度、执行节奏、市场变化和平台环境等因素影响，我们会在约定范围内持续沟通和优化。

### 3.6 合作邀请

目的：以自然的商业行动结束页面，不使用防御式收尾。

建议文案：

> 好的合作，从真实、清晰和彼此信任开始。如果你希望了解客来宝如何结合具体业务提供支持，欢迎与我们沟通。

主要操作：

- 主链接：“联系我们”，目标为 `/contact`。
- 次链接：“返回首页”，目标为 `/`。

## 4. 内容与界面变更范围

### 4.1 页面正文

在 `src/app/disclaimer/page.tsx` 中：

- 将页面标题改为“合作与使用说明”。
- 替换 lead 文案。
- 将七个原有章节重组为四项品牌承诺。
- 更新目录标签和锚点 ID，使其与四项承诺一致。
- 将底部操作文案改为自然的联系入口；若 `PolicyLayout` 不支持页面级操作文案，则以最小改动扩展其可配置能力，默认行为保持不变。

### 4.2 全站入口与元数据

- `src/app/privacy/page.tsx`：可见标题改为“信息与隐私说明”，正文和目录不变。
- `src/app/terms/page.tsx`：可见标题改为“合作服务说明”，正文和目录不变。
- `src/components/site-footer.tsx`：三个入口名称依次改为“信息与隐私说明”“合作服务说明”“合作与使用说明”。
- `src/components/site-footer.tsx`：将当前按金融、保险、投资和结果逐项否定的页脚摘要，改为真实性、清晰合作和合理预期的通用说明；该调整会同步影响所有使用公共页脚的公开页面。
- `src/lib/route-metadata.ts`：同步更新三个政策页的 title；`/disclaimer` 的 description 改为品牌承诺口径，不再列举职业资质、直销、保险和证券；`/privacy` 与 `/terms` 的 description 仅在含有旧页面名称时做必要替换。
- 保持 `/privacy`、`/terms`、`/disclaimer` URL、canonical 和 sitemap 路径不变。

### 4.3 需求文档同步

原 `FR-06` 明确要求 `/disclaimer` 完整覆盖职业资质、所属机构审核、保险、证券、投资、直销和效果不保证，与本次产品决策冲突。实施前应更新：

- `docs/1-Requirement/Mainland-Website-FR/FR-06-policy-privacy-and-claims-boundary.md`；
- 直接引用上述完整覆盖要求的 SRS、FR 索引或下游 Sprint；
- 将页面要求改为真实性、合作责任、授权和合理成果预期四类原则。

本次修改不等同于法律审查，也不对现有其他页面中的行业边界作自动删除。若后续需要统一全站口径，应另行确认范围。

## 5. 测试与验收

### 5.1 自动化检查

- 更新 `tests/fixtures/m4-02-public-page-baseline.json` 中三个政策页的 H1，并更新 `/disclaimer` 的 H2、markers 和 section labels。
- 更新或新增内容契约断言，确认四项承诺、联系入口和目标 URL 存在。
- 确认页面不再出现原七段目录标题和旧 metadata 描述。
- 确认公共页脚入口及摘要使用新的通用合作口径。
- 确认 `/privacy` 与 `/terms` 除页面名称及必要 metadata 外，正文和目录没有变化。
- 运行 `pnpm test && pnpm lint && pnpm build`。

### 5.2 页面检查

- 在 320px、390px、768px 和 1440px 视口检查目录、正文、锚点和底部链接。
- 确认正文无横向溢出，标题层级正确，政策页阅读宽度保持现状。
- 确认三个政策页、页脚入口、canonical 和 sitemap 均可正常访问。

### 5.3 文案验收

- 开场不使用“防止误解”“不构成”或连续否定式措辞。
- 四项承诺均以合作原则开头，同时包含必要的双方责任说明。
- 不出现具体职业、直销、保险、证券或投资边界清单。
- 不承诺客户数量、成交、收入、流量、排名或其他确定成果。
- 结尾提供明确且自然的联系行动。

## 6. 非目标

- 不改写 `/privacy` 或 `/terms` 的政策正文与目录。
- 不删除其他销售页、职业页或页脚摘要中的现有行业边界。
- 不更改联系表单、服务流程、价格或产品能力。
- 不引入 CMS、数据库或新的后台配置。
- 不把本页包装为法律意见或专业合规审查结论。
