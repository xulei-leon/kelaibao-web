# FR-04 企业微信首要咨询入口

- `FR-ID`: `FR-04`
- `标题`: 企业微信首要咨询入口
- `所属阶段`: 阶段 2 - 线索转化
- `开发顺序`: 4
- `优先级`: P0
- `前置依赖`: `FR-01`
- `涉及包`: 微信联系配置、二维码静态资源、微信 CTA、弹层、`/contact`
- `是否属于原型阶段`: 是
- `来源类型`: 新需求
- `原始 SRS 章节`: 4、5、6.6、7.2、10、11.2
- `相关 FR`: `FR-02`、`FR-03`、`FR-05`、`FR-07`

## 目标

用不接入微信 API 的最小实现，为桌面端和移动端访问者提供稳定、可访问、可降级的企业微信咨询入口。

## 背景与问题

企业微信二维码符合当前人工成交方式，但同一手机无法直接扫描屏幕、二维码资源可能失效，且弹层需要满足键盘与移动端使用要求。

## 影响范围

- 集中的 `WechatContactConfig`。
- 本地二维码资源、全站微信 CTA、轻量弹层和联系页主入口。
- 匿名 CTA 分析事件及相关测试。

## 需求描述

1. 正式生产使用企业微信后台生成的“联系我”二维码，并作为本地静态资源部署。
2. 首页、服务页、职业页和联系页共用一份微信配置。
3. 桌面端显示扫码说明；移动端显示长按识别或保存图片说明。
4. CTA 打开轻量弹层；无法打开或脚本不可用时跳转 `/contact`。
5. 弹层支持关闭按钮、焦点进入与恢复、Escape 关闭、替代文本和文字说明。
6. 二维码加载失败时显示错误提示和备用表单入口。
7. 只记录事件名和来源页面等匿名“打开微信联系方式”事件。
8. 不实现微信 API、自动唤起、扫码身份追踪、好友状态或自动消息。

## 高层要求

- 不使用小程序、公众号关注链路、群二维码、URL Scheme、开放标签或微信客服 API。
- 二维码不得使用不受控的第三方图片 URL。
- 测试个人微信二维码必须通过配置显式标记，生产门禁禁止该标记。
- 分析事件不得包含联系人或表单数据。

## 输入

- `WechatContactConfig`。
- `/wechat/contact-qr.png` 等本地资源。
- CTA 来源页面标识。

## 输出

- 全站一致的微信 CTA、弹层和 `/contact` 主入口。
- 匿名 CTA 事件。
- 二维码失败降级状态。

## 失败与降级

- JavaScript 不可用：普通链接进入 `/contact`。
- 二维码加载失败：显示文字说明和备用表单入口。
- 分析失败：不影响 CTA、弹层或导航。

## 不纳入范围

- 微信身份、好友关系、消息、群聊或客服系统集成。
- 扫码转化归因和个人级跟踪。
- 备用表单的 HTTP 提交实现。

## 最小验证方式

- 运行组件测试、可访问性测试、类型检查和生产构建。
- 手工检查桌面扫码、移动长按说明、无脚本和资源失败场景。
- 检查分析事件载荷不含个人信息。

## 验收要点

- 全站 CTA 共用同一二维码和文字配置。
- 桌面与移动提示正确，二维码可显示和保存。
- 弹层键盘行为和焦点恢复正确。
- 任一交互失败时均可到达 `/contact` 或备用表单。
- 正式生产配置不允许个人微信二维码。

## 备注

企业微信账号、二维码和服务时间属于 `FR-08` 的生产配置门禁。
