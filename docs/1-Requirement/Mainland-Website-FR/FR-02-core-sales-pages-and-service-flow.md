# FR-02 核心销售页面与定制服务流程

- `FR-ID`: `FR-02`
- `标题`: 核心销售页面与定制服务流程
- `所属阶段`: 阶段 1 - 核心获客体验
- `开发顺序`: 2
- `优先级`: P0
- `前置依赖`: `FR-01`
- `涉及包`: 首页、`/services`、`/method`、`/about`、全局导航与内容配置
- `是否属于原型阶段`: 是
- `来源类型`: 新需求
- `原始 SRS 章节`: 2、3、5、6.1～6.5
- `相关 FR`: `FR-03`、`FR-04`、`FR-06`

## 目标

让访问者在核心销售页面中识别赛诺全网的服务对象、三类服务、人工合作流程和效果边界，并顺利进入微信咨询。

## 背景与问题

赛诺全网没有现有页面或可复用英文内容，需要用适合中国大陆个人从业者的独立表达建立首个完整销售路径。

## 影响范围

- 首页、服务页、方法页、关于页。
- 页头、页脚、导航、服务卡片、流程和 CTA。
- 品牌与服务内容契约测试。

## 需求描述

1. 首页首屏说明品牌、个人从业者定位、三类服务及微信主 CTA。
2. 首页展示直销、保险、证券入口和人工沟通至站外交付的完整流程。
3. `/services` 展示三类服务的适用情况、范围、代表性交付物和限制。
4. `/method` 说明了解现状、确定定位、建设内容、规划推广和阶段复盘。
5. `/about` 说明主体、能力、服务原则和联系路径；未确认信息使用明确占位且不得进入生产。
6. 所有服务 CTA 使用同一微信入口；微信组件由 `FR-04` 实现。
7. 页面不得出现固定价格、购买、注册、登录、免费诊断或结果承诺。

## 高层要求

- 页面组合集中内容，不复制核心服务和声明口径。
- 不虚构案例、客户评价、资质或合作机构。
- 方法与交付示例必须标记为结构示例，不伪装为效果证据。
- 核心页面应静态生成。

## 输入

- `FR-01` 的品牌、服务、流程和 CTA 配置。
- 经确认的主体与联系方式占位状态。

## 输出

- 四个核心销售页面和完整导航路径。
- 可复用的服务展示、流程与免责声明展示组件。
- 内容契约测试。

## 失败与降级

- 微信弹层不可用时 CTA 跳转 `/contact`。
- 主体或联系方式尚未确认时不得生成虚假内容，生产门禁由 `FR-08` 阻止发布。

## 不纳入范围

- 三个职业详情页。
- 微信二维码交互和备用表单。
- 在线报价、支付、案例页或客户账号。

## 最小验证方式

- 运行 `pnpm test && pnpm lint && pnpm build`。
- 内容契约检查品牌、三类服务、流程、CTA 和禁止用语。
- 手工检查移动端与桌面端核心路径。

## 验收要点

- 首屏可识别“赛诺全网”、服务对象、三类服务和微信 CTA。
- 服务页清晰说明人工定制与人工报价。
- 方法页区分专业表达服务和职业/金融专业意见。
- 所有核心 CTA 可到达微信入口或 `/contact`。
- 页面无固定价格、付款、账号或保证结果内容。

## 备注

职业专属文案和限制由 `FR-03` 管理；通用声明由 `FR-06` 管理。
