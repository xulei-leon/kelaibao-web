# FR-01 独立项目壳与集中内容基础

- `FR-ID`: `FR-01`
- `标题`: 独立项目壳与集中内容基础
- `所属阶段`: 阶段 1 - 产品基础
- `开发顺序`: 1
- `优先级`: P0
- `前置依赖`: `../Kelaibao-Unified-Website-SRS.md`
- `涉及包`: `products/sino-cn/`（待创建的独立 Next.js 工程）
- `是否属于原型阶段`: 是
- `来源类型`: 新需求
- `原始 SRS 章节`: 1、2、4、7、8
- `相关 FR`: `FR-02`、`FR-03`、`FR-04`

## 目标

建立可独立安装、构建、测试和部署的赛诺全网项目壳，并集中维护品牌、服务、职业、微信配置和免责声明，为所有后续页面提供稳定基础。

## 背景与问题

当前只有 SRS，没有中文站代码。英文站服务不同客户且部署在不同区域，复用其工程或组件会增加耦合和回归风险。

## 影响范围

- 新建中文站工程、路由布局、全局样式、内容配置和基础测试。
- 建立独立依赖、构建配置和环境变量说明。
- 不修改 `products/sino-en/`。

## 需求描述

1. 使用独立、静态优先的 Next.js 项目，默认输出可抓取 HTML。
2. 建立中文根布局、页头、页脚、跳转主内容链接、404 和全局错误降级。
3. 集中定义品牌、三类服务、三个职业、全局 CTA、微信联系配置和声明文本。
4. 内容模型采用 SRS 规定的稳定 ID，不包含价格、付款链接或账号入口。
5. 提供独立的 `package.json`、TypeScript、样式、测试、构建和环境变量样例。
6. 源码、依赖和构建脚本不得引用 `products/sino-en/`。

## 高层要求

- 不提前建设数据库、Auth、CMS、CRM 或共享包。
- 外部能力只允许通过明确的 HTTP(S) endpoint 集成。
- 核心内容必须由服务端或静态构建输出，不能依赖客户端脚本加载。
- 320px 以上视口不得出现全局横向正文溢出。

## 输入

- 品牌名称“赛诺全网”。
- 服务、职业和声明内容配置。
- `NEXT_PUBLIC_SITE_URL` 等公开运行配置。

## 输出

- 可运行的独立中文站工程壳。
- 集中内容与配置类型。
- 基础路由布局、全局样式和工程验证脚本。

## 失败与降级

- 非必要配置缺失时仍可本地构建；相关功能由后续 FR 提供降级。
- `NEXT_PUBLIC_SITE_URL` 非法时构建或配置校验应给出明确错误，不生成错误 canonical。

## 不纳入范围

- 完整销售页面内容、微信弹层和询盘表单。
- 生产备案、域名和正式二维码配置。
- 英文站迁移或共享组件抽取。

## 最小验证方式

- 工程建立后运行 `pnpm test && pnpm lint && pnpm build`。
- 检查构建不引用 `products/sino-en/`。
- 检查中文根布局、404 和基础导航在 320px 与桌面视口可用。

## 验收要点

- 项目可在自身目录独立安装、测试和构建。
- 内容配置只维护一份，并具有稳定类型和 ID。
- 构建输出包含中文根布局及可抓取基础内容。
- 英文站源码、配置、测试和构建行为没有变化。

## 备注

本 FR 只建立最小产品壳；任何共享代码提议必须基于后续已验证的真实重复需求另行立项。
