- `FR-ID`：`FR-25`
- `日期`：2026-10-20
- `来源`：用户要求“删除可通过内容编辑修改 news 的功能要求，把 news 和案例也改为普通的静态页面”。
- `优先级`：P0
- `状态`：LOCAL_CODE_READY_WITH_EXTERNAL_LEGACY；代码与本地验证完成，真实内容迁移/云部署待验证。
- `关联`：替代 FR-12 的 CMS 生命周期、FR-24 的自主编辑及其补充；调整 FR-13 的内容来源与缓存；FR-10/FR-11 中仅服务 CMS 的能力不再是目标功能。
- `设计`：[当前提交分析与静态内容设计](../../2-Design/Static-News-and-Cases-Spec.md)
- `实施计划`：[M5-05](../../3-Plan/sprint-m5-05-static-news-and-cases.md)

## 目标与范围

新闻和案例与其他普通公开页面一样，由开发者在仓库内维护，通过代码审查、构建、部署更新。保留 `/news`、`/news/[slug]`、`/cases`、`/cases/[slug]` 及首页、关于页的摘要入口；不再要求非技术管理员在后台维护内容。

本需求中的“静态”指构建期确定公开内容和生成页面，生产请求不读取内容数据库、不调用 CMS 或远端内容 API、不依赖客户端取数。允许使用 Next.js 静态生成和受控代码数据模块，不引入通用页面搭建器。整个应用继续在 ESA → FC 全栈 Next.js 上运行，`/api/inquiry` 与 DirectMail 保留；不要求整站静态导出。

## 撤销的功能要求

- 新闻、案例的后台列表、创建、HTML 编辑、草稿保存、预览、发布、下线、重新发布、删除、修订历史与自动 Slug 操作。
- CMS 图片选择、预签名上传、上传确认、封面绑定与后台授权勾选。
- 为这些操作设置的 revision/pointer、expectedVersion、审计、数据库事务、purge outbox/worker 和“无需构建即可发布”的验收要求。
- 仅为上述 CMS 服务的 `/admin/*`、`/api/admin/*` 和认证入口；迁移完成后应移除这些入口及仅被其使用的代码、依赖、测试与操作说明。若发现独立用途，先记录具体调用和处理范围，不能仅凭目录名删除共享代码。

旧 FR/Sprint/评审/证据保留为历史记录，其“已实现”只描述旧版事实，不再构成新版本必须保留 CMS 的约束。

## 静态内容与发布契约

1. 新闻和案例的标题、摘要、正文、稳定 slug、首次发布日期、修改日期、图片和 alt 随代码维护。可用 TS/TSX 内容模块与共用模板，无需为每篇重复布局，也不新增 Markdown/MDX 编辑系统。
2. 内容只有进入本次发布清单才会公开；未准备好的材料不进入公开模块、客户端包或制品。列表按发布日期降序，相同日期按 slug 稳定排序；无文章时显示现有空状态，不伪造内容。
3. 每种类型内 slug 唯一，公开后保持原路径；修改标题不改变 slug。修改路径需逐条登记永久重定向，不得静默重建所有 URL。
4. 新增、修改、撤回均通过代码变更、审查、构建和部署完成；不提供网页编辑入口，不在请求时写入内容或自动从数据库回退读取。
5. 案例、Logo、照片及结果口径仍需发布前授权/证明，并在仓库证据中记录来源、范围、复核人与日期；不再通过后台勾选作为门禁。内部证明和个人资料不得进入公开包。
6. 正文采用代码维护的受控组件；确需迁入旧 HTML 时先按允许策略清理并审查，不执行任意 HTML、脚本、内联事件、危险协议或第三方嵌入。不为此保留在线 HTML 编辑器。
7. 图片随现有静态资源构建/交付流程管理，不依赖媒体数据库或浏览器上传。既有 OSS 图片需逐个验证授权、可达性和版本稳定性；不关闭 Bucket 或删除原对象。

## URL、SEO 与缓存

- 列表、详情的首次 HTTP 响应含完整可抓取内容；保留唯一 title/description、canonical、Open Graph、新闻 `NewsArticle`、案例 `Article` 和面包屑等结构化数据。
- sitemap、RSS 和实验性 `llms.txt` 从同一份静态公开清单生成，与页面在同一部署中更新，运行时不得查询内容 repository。RSS 保持现有类型范围，不擅自扩大收录。
- 未知 slug 返回真实 `404`。已经公开后撤回或旧版已下线/删除的 URL，以代码维护的撤回清单返回真实 `410`；草稿不导出。跳转、撤回清单不得依赖旧数据库在线查询，也不得与公开清单重叠。
- 410 可以由 FC 服务端受控路由实现，以真实状态码为准；不能仅渲染“已下线”文案并返回 200。静态正文要求不限制错误状态的服务端处理。
- 新闻、案例和发现文件采用与普通静态页面相同的发布版本缓存；不再要求 CMS 的 60 秒内即时更新或事务 purge。部署必须精确刷新受影响的列表、详情、发现文件、摘要入口和撤回/重定向 URL，并在开放新版本流量前检查一致性；刷新失败停止切流或回退，不能声称发布完成。
- Preview 禁止索引和 Production 发布门禁保留；不承诺 SEO/GEO 排名、推荐、AI 引用或流量。

## 迁移与数据保护

实施前盘点实际数据库中的已公开、草稿、下线/删除内容、slug、时间、图片与授权。只有经过核对且有权公开的 published snapshot 转为静态内容；不能把工作草稿当作公开正文。没有真实数据访问权限时记录迁移缺口，不以空列表认定“没有历史文章”。

保留数据库、migration 历史、修订、审计和原媒体，迁移不执行 DROP、清库、删除对象或注销云资源。RDS/私有 OSS 的采购、退役和成本重算属于另行确认的基础设施变更；本规格只解除新闻/案例页面与发现文件对 CMS 数据库的依赖，不据此宣称整个应用已无需 RDS。

切换前对照内容与 URL 清单并备份，停用旧 CMS 写入口，防止导出后继续编辑造成版本分叉；验证失败回退上一 FC 版本及对应缓存策略。回退所需旧表和媒体须保持可用。

## 验收

- 无内容数据库/不可用数据库条件下构建并访问列表、详情、404/410 与发现文件，内容一致，不发生内容 repository 查询。
- 不运行客户端 JS 仍可阅读正文；canonical、日期、结构化数据、图片、内链和发现文件一致，草稿、撤回与未知 URL 不进入发现文件。
- 新增或修改代码内容后，构建部署才改变页面；后台编辑入口和 CMS mutation API 不再可用。
- 历史文章逐条对应已保留原路径、永久跳转或真实 410，无未核对的数据丢失；授权证明和私人草稿不进入公开制品。
- `pnpm test`、`pnpm lint`、`pnpm build`，以及涉及制品/发布时的 `pnpm smoke:standalone`、`pnpm validate:release`；检查 320、390、768、1440px，包含列表、正文长标题、图片与空状态。
- 报告区分规格完成、代码完成、本地验证与真实部署证据；本地代码完成不能关闭 Production blocker；结果见 [M5-05 验收](../../5-Evidence/m5-05/README.md)。
