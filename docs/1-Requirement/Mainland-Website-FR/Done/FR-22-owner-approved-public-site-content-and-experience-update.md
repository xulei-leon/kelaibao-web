## 目标

把产品负责人在 `20260804-kelaibao-website-review.docx` 中针对 `products/kelaibao/` 当前网站提出并于 2026-08-04 明确全部接受的 56 项意见，转换为可实现、可验证、可审计的公开站需求：完成品牌色与 Logo、全站命名和导航、首页/功能/团队/媒体/新闻/关于内容与排版、联系流程、政策结构以及正式候选图片调整，同时保持单一客来宝官网、K-Link 产品、客来宝媒体子业务和既有全栈安全架构不变。

## 背景与问题

M4-03 完成了视觉系统和可替换素材，但用户可见文案、信息架构与交互在当时被冻结。新的产品负责人审阅稿解除该冻结并提出完整改版方向，其中既有低风险视觉修正，也有结果型口径、媒体范围、产品数据行为、政策和正式素材等需要同步变更来源文档与 Production 门禁的内容。

产品负责人要求所有意见均为 `Accept`。因此本 FR 不删除任何一项意见；对证据未齐的意见，采用“纳入实现计划 + 显式阻塞 Production”的处理，不用静默弱化、拒绝或伪造证据替代。

## 影响范围

- 全局：品牌 Token、Logo、Header、Footer、导航、metadata 与公共内容常量。
- 页面：`/`、`/features`、`/team`、`/media`、`/news`、`/about`、`/contact`、`/privacy`、`/terms`、`/disclaimer` 及必要的效果责任入口。
- 交互：小程序体验 Dialog、媒体咨询 Dialog、联系表单、图片 Gallery/Dialog。
- 数据与集成：电话号码字段 DTO、DirectMail HTTPS 请求、PII 日志/存储/分析边界。
- 文档与证据：SRS、视觉规格、内容布局规格、claims register、素材 provenance、Production gate 报告和 M4-04 视觉 QA。

## 需求描述

### 1. 全局品牌、颜色与导航

1. 全站主色采用 `#094092`，辅色采用 `#3f6cc4`；建立语义 Token，覆盖按钮、主标题、背景、边框、hover、active 与 focus-visible，且保留媒体咨询、错误和正文的独立语义色。
2. Header 使用审阅稿提供的客来宝/K-Link 正式候选 Logo；上线前记录来源、授权、尺寸、透明背景和替代文本。
3. Header 描述改为“K-Link 一站式拓客工具系统”。
4. 导航与 Footer 的“客来宝媒体”入口改为“媒体中心”；`/media` 内仍可用“客来宝媒体”说明子业务身份，不创建第二品牌或第二站点。
5. 导航正文使用黑色 `#000000`，所有状态满足可访问性阈值。
6. Footer 标语改为“内容赋能 资源链接 商机互联”，移除“了解客来宝”下的案例入口，但不删除 `/cases`、CMS 或发现能力。

### 2. 首页

1. Hero 中“熟人筛完后，下一个客户，去哪找？”降级字号；新增长结果口径与“客来宝----让更多潜在客户添加你”不得覆盖 Banner。
2. 首页采用产品负责人确认的“每天1分钟，把沉睡微信群变成你的私域客户池！”口径；实现前必须更新 claims register，记录算法、触达去重、归因、观察周期、客户定义、负责人、来源与公开授权。
3. 四类工具移除外层灰底，保留各模块独立背景色。
4. 五步流程突出“查找、转发、信任、实时、复制”，以语义 HTML 和响应式步骤组件实现；若最终使用固定图片，必须保留等价文本、alt 和移动端清晰度。
5. 四大模块采用产品负责人确认的效率文案、标点修正和语义图标；效率口径进入 claims register 并受 Production 证据门禁约束。
6. 媒体传播模块采用两组三行文案，删除 01～04 编号并增加图标；“合规发布”“官方媒体”“实时收录”“数据反馈”分别登记适用范围与证据。
7. 删除独立“产品与传播边界”模块；等义边界必须保留在 Hero/CTA 临近说明、Footer 与政策页，不能造成结果保证或业务身份误读。

### 3. 政策、隐私与责任

1. Footer 政策入口调整为“政策与使用原则”“隐私保护原则”“技术中立原则”“用户行为规范”“效果与责任说明”。
2. 采用审阅稿提供的隐私保护、技术中立、用户行为与效果责任正文作为批准内容输入。
3. `/privacy` 仍必须说明真实收集字段、目的、接收 endpoint、共享范围、保存期限与用户权利；通讯录、私人关系链、账号信息和使用数据的断言必须与 K-Link/官网真实数据流一致。
4. 技术中立和用户行为规则必须明确适用对象、第三方平台依赖、内容处置权限、客户责任及联系/申诉路径，不能声明尚不存在的管理能力。
5. “效果与责任说明”作为跨页面结果声明来源，明确平台不承诺固定收益、客户数量或商业结果。
6. 保持现有 URL 的 canonical/发现连续性；若新增效果责任路由，必须更新 sitemap、metadata、测试和 Footer，并避免重复政策冲突。

### 4. 体验、咨询与联系表单

1. 小程序体验文案改为“使用微信打开小程序，按小程序内说明指引进行体验。”
2. 从体验 UI 删除“官网不创建公众账号、产品 Dashboard，也不收集小程序内客户行为”，但在隐私政策和架构契约中保留等义事实。
3. 联系页使用三个留白充分的模块；删除指定的产品/媒体区分长文，但必须继续以标题、图标、CTA、资源、事件与失败路径维持两条流程隔离。
4. 媒体咨询入口改为“人工服务咨询”/“咨询媒体报道”，删除指定筛选说明，同时保留服务目的、响应预期和失败降级。
5. 表单标题改为“提交表单，等待人工服务”，联系方式字段改为电话号码；同步 DTO、服务端校验、DirectMail 模板、隐私说明、错误状态和测试。
6. 姓名、电话号码和需求不得进入 URL、Web Storage、分析事件、应用日志或线索数据库；DirectMail 继续通过明确 HTTPS API 调用。
7. 图片只能作为获批准的辅助说明，不能替代表单、按钮、二维码或关键可访问文本。

### 5. 核心功能与团队方案

1. 修正“私域营销（（持续曝光与私域引流）”为单括号文本。
2. 删除功能页独立“产品能力边界”模块；等义限制分布到 Hero、能力卡临近说明和政策入口。
3. 团队 Hero 和引语按审阅稿换行、字号与标点调整。
4. 采用审阅稿提供的团队效率、带教、复制、私域锁客、分享者归属和后台线索文案。
5. 对“每天节省 1 小时”“一年多出 2 个月”“业绩倍增”“提升成交率”“彻底消除”“不抢流量”“不越级留存”“线索只保留在 A 后台”等逐项登记定义、产品版本、样本、算法、异常场景、数据流、授权和责任人。
6. 官网只介绍经确认的 K-Link 行为，不在本仓库实现公众账号、团队权限、产品 Dashboard 或线索数据库。
7. 删除团队页独立“团队方案边界”模块；等义限制保留在能力卡、CTA 临近说明和政策入口。

### 6. 媒体中心与新闻

1. `/media` 的导航/栏目名改为“媒体中心”，页面主体仍可说明“客来宝媒体”是客来宝旗下子业务。
2. CTA 改为“咨询媒体报道”，Dialog 与 analytics 的可访问/显示文案同步更新，企业微信资源和失败路径不变。
3. “你为什么需要媒体背书？”四个痛点并列显示并增加图标，01/04 使用白底；移动端采用可读单列或双列。
4. 核心价值采用“客户搜索即可看到优质内容”；该搜索结果口径进入 claims register 和专业审查，Production 在证据完成前保持阻塞。
5. 新增“百家主流媒体全覆盖”模块，使用审阅稿媒体名单；建立媒体资源范围、合作/可投状态、更新时间、授权和实际项目审核说明。
6. 新闻页 Banner 改为“新闻中心”，删除“客来宝发布的公开动态、方法说明与市场观察。”，保持 SSR、canonical、JSON-LD、RSS、sitemap 和 CMS 生命周期不变。

### 7. 关于我们与正式候选图片

1. `/about` Hero 改为“关于我们”，公司介绍成为独立模块并采用审阅稿四段正文。
2. 公司主体、专家/顾问资历、业务范围及增长/成交/管理相关表述必须有来源和公开授权登记。
3. 删除“合作伙伴/服务案例”模块，不删除获授权案例 CMS 与 `/cases` 能力。
4. “实景图”改为“公司实景”；办公室场景和到访指引采用点击查看的可访问 Gallery/Dialog。
5. 使用审阅稿提供的办公室合成图和到访指引长图作为正式候选资产；上线前核对人物、Logo、屏幕、地址、电话、二维码、来源和授权，并提供文本版到访路线。

### 8. 决策覆盖与追踪

1. `20260804-kelaibao-website-review-confirm.md` 的 56 行均为必追踪项，不得在实现中静默删除或改回 Partial/Reject。
2. 实现证据必须提供“Review Cxx -> FR 条款 -> 代码/内容文件 -> 测试 -> 证据”的映射表。
3. 外部证据缺失只影响 Production 状态，不取消已接受需求；每个阻塞项必须记录责任人、所需证据和解除条件。

## 高层要求

- 客来宝继续是唯一主品牌，K-Link 是产品名，客来宝媒体是 `/media` 内子业务；“媒体中心”是导航/栏目名，不形成第二应用或第二 Organization。
- 不新增公众注册、支付、CRM、自动报价、预约、微信 API、产品 Dashboard 或线索数据库。
- 所有第三方集成直接使用明确 HTTP(S) API，不创建通用 `webservice`。
- 生产架构继续为 ESA -> Function Compute 全栈 Next.js -> RDS MySQL + 私有 OSS，询盘通知继续使用 DirectMail。
- SEO/GEO 仍以技术基线和可审计口径为边界；结果型文案必须进入 claims register 和 Production gate，不能用本地测试或负责人决定冒充客观证明。
- 页面删除独立边界模块后，必须以更贴近相关 CTA/能力的方式保留等义约束，且政策入口持续可见。

## 失败与降级

- 口径证据、媒体范围、产品行为、主体资历或图片授权缺失：允许继续完成不依赖该证据的本地实现，但对应公开文案/资产不得进入 Production，状态保持 `BLOCKED`。
- Logo、办公室图或到访图加载失败：保留稳定布局、替代文本和文本版联系/路线，不请求远程兜底图。
- 电话表单提交失败：显示明确错误，不自动重试，不记录 PII，并保留企业微信人工咨询路径。
- Gallery/Dialog 失败：图片链接可退化为普通可访问链接或内联内容，不丢失必要文本。
- 搜索与媒体平台结果不可控：不得通过测试桩、截图或本地数据关闭客观结果证据门禁。

## 不纳入范围

- 新增 CMS 内容类型、通用页面 CMS、数据库 schema 或跨应用内容 API。
- 关闭备案、域名、云资源、专业审查和真实授权等既有 Production 外部门禁。
- 代替业务负责人、法律/合规人员或媒体平台出具客观证明。
