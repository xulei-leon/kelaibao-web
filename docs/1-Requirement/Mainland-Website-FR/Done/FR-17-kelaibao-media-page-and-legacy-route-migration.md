# FR-17 客来宝媒体单页与旧顾问路由迁移

- `FR-ID`: `FR-17`
- `标题`: 客来宝媒体单页与旧顾问路由迁移
- `所属阶段`: 阶段 3 - 客来宝统一官网改版
- `开发顺序`: 17
- `优先级`: P0
- `前置依赖`: `FR-15`、`FR-16` 在 M3-02 交付的产品页面、小程序配置和联系分流
- `涉及包`: `products/kelaibao/src/app/media/`、旧服务/职业/方法路由、联系组件、metadata、测试
- `是否属于原型阶段`: 否
- `来源类型`: 需求变更
- `原始 SRS 章节`: 现有 SRS 第 4.2、6.3～6.8、10、11 节；本 FR 将原多页面顾问站收敛为 `/media`
- `相关 FR`: `FR-02`、`FR-03`、`FR-04`、`FR-06`、`FR-07`

## 目标

将原赛诺顾问业务更名为“客来宝媒体”，在客来宝统一官网内以单页 `/media` 保留其专业表达与内容顾问定位，并通过永久重定向安全收敛旧公开路由。

## 背景与问题

新方案不再允许赛诺作为独立网站或多页面子站，但用户已确认保留原顾问业务定位。现有 `/services`、`/for/*`、`/method` 分散承载服务、职业场景和方法内容，需要压缩为一个可理解、可咨询、具有合规边界的页面，同时避免已有链接直接失效。

## 影响范围

- 新建 `/media`。
- 迁移 `/services`、`/for/direct-sales`、`/for/insurance`、`/for/securities`、`/method`。
- 原服务、职业、方法内容模型和组件。
- 企业微信二维码 CTA、联系页、metadata、sitemap、导航和重定向测试。

## 需求描述

1. `/media` 必须使用“客来宝媒体”名称，并明确它是客来宝旗下专业表达与内容顾问业务。
2. 页面必须依次说明：
   - 专业定位与个人形象。
   - 内容资产建设。
   - 持续推广顾问。
   - 直销、保险、证券及其他审慎表达专业人士的适用场景。
   - 五步方法、代表性交付、合作方式和适合/不适合情形。
   - 职业资质、功效、收益、金融建议和平台分发边界。
3. 页面必须复用全站共享的客来宝页头、页脚、字体、颜色 Token 和组件，不得建立独立 Logo、导航或 Organization 结构化数据。
4. “咨询客来宝媒体”只打开企业微信二维码；Dialog 标题使用“咨询客来宝媒体”，二维码 alt 使用媒体咨询语义，匿名事件固定为 `open_media_wechat_contact`，失败链接固定到 `/contact#media-consultation`。不得打开 K-Link 小程序、复用 `open_mini_program_trial` 或暗示产品试用。
5. `/contact` 必须保持两条入口语义分离。
6. 以下旧路由必须永久重定向：
   - `/services` → `/media#services`
   - `/for/direct-sales` → `/media#direct-sales`
   - `/for/insurance` → `/media#insurance`
   - `/for/securities` → `/media#securities`
   - `/method` → `/media#method`
7. `/about` 必须保留为客来宝公司介绍，不得重定向。
8. sitemap、`llms.txt`、适用的 RSS、metadata/canonical、Open Graph URL、JSON-LD 和站内导航不得继续链接已经迁移的旧页面，只使用 `/media` 或其稳定锚点。M3-03 必须把所有现有顾问/服务/方法链接发射点收敛到 `/media`；最终六项产品主导航和完整 Header/Footer 外壳仍由 M3-04 切换。
9. 旧路由重定向必须保留 query string；页面锚点必须对应稳定、唯一的 section `id`。

## 高层要求

- 使用 Next.js 原生永久重定向能力，不引入重定向依赖或 Host 路由。
- 重定向必须由真实 HTTP 契约验证为 `308`（或 Next.js 当前原生永久重定向的等价永久状态），`Location` 同时保留原 query 和目标 fragment；仅检查配置对象不足以完成验收。
- 对当前公开源码和渲染输出执行旧路径 allowlist 检查；五条旧路径只允许出现在原生 redirect 定义、重定向测试和历史文档中，不得继续由首页、页脚、移动 CTA、内容卡片、metadata 或发现文件发出。
- 复用现有服务、职业、方法和企业微信组件；只在内容边界需要时拆分。
- 职业限制是验收条件，不得因压缩为单页而删除。
- “客来宝媒体”不得拥有独立 CMS 内容类型或数据库表。

## 输入

- 现有服务、职业、方法、关于和联系内容。
- 已确认的客来宝媒体名称、业务定位和企业微信配置。
- 客来宝品牌基础，以及 M3-02 已交付的小程序/企业微信配置隔离。

## 输出

- `/media` 单页。
- 五条永久重定向。
- 产品体验与媒体咨询两条可区分 CTA。
- 更新后的 sitemap、metadata 和导航契约。

## 失败与降级

- 企业微信二维码失败时显示 `/contact` 中的顾问咨询说明；不得退回小程序二维码。
- 旧路由目标不存在或锚点缺失时测试必须失败，不允许重定向到首页。
- 未配置正式企业微信时保持 Preview/Production `BLOCKED`，可使用明确标记的测试资产进行本地验证。

## 不纳入范围

- `/media/*` 多页面结构。
- 独立媒体品牌视觉、子域名、导航、CMS 或结构化数据实体。
- 顾问在线预约、报价、支付或客户账号。
- 修改 K-Link 产品功能和团队方案。

## 最小验证方式

- `/media` 内容、品牌、section `id` 和 CTA 组件测试。
- 五条旧路由的配置契约与真实 HTTP 永久状态、query 保留和目标锚点测试；未知 `/for/*` 不得误重定向到首页或其他职业锚点。
- sitemap、`llms.txt`、适用的 RSS、metadata/canonical、Open Graph URL、JSON-LD 和导航不包含旧路由。
- 企业微信与小程序二维码入口隔离测试，并保留企业微信 Dialog 的 accessible name、焦点进入/闭环/恢复、Escape/关闭按钮、图片失败状态公告与正确备用锚点。
- `pnpm test && pnpm lint && pnpm build` 及四个关键视口检查。

## 验收要点

- `/media` 在一个页面内完整保留原顾问业务的服务、职业和合规边界。
- 用户能够明确区分 K-Link 免费体验与客来宝媒体人工咨询。
- 旧链接不会失效或错误进入首页。
- 页面视觉和结构始终属于客来宝统一官网。

## 备注

本 FR 已由 `sprint-m3-03` 完成实现、单 reviewer 文档/代码 review-confirm、全量验证和本地域名内迁移验收。旧独立域名是否存在仍由发布前 DNS/访问清单核实；只有确有已公开域名时才配置边缘层永久重定向。
