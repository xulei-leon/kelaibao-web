# FR-16 客来宝产品官网与小程序体验入口

- `标题`: 客来宝产品官网与小程序体验入口
- `所属阶段`: 阶段 3 - 客来宝统一官网改版
- `开发顺序`: 16
- `优先级`: P0
- `前置依赖`: [FR-15](FR-15-kelaibao-brand-and-project-migration.md)
- `涉及包`: `products/kelaibao/src/app/`、`src/components/`、`src/lib/`、`public/`、`tests/`
- `是否属于原型阶段`: 否
- `来源类型`: 需求变更
- `原始 SRS 章节`: 现有 SRS 第 4、6.2～6.7、7、8、10、11 节；页面内容以新版工作簿和统一官网设计为准
- `相关 FR`: `FR-02`、`FR-04`、`FR-05`、`FR-07`

## 目标

将公开站主销售路径改造成客来宝/K-Link 产品官网，使直销人员和团队管理者能够理解产品价值、十项工具、团队方案与公司信息，并通过无 Web 注册的小程序二维码直接申请免费体验。

## 背景与问题

现有首页、服务页和职业页销售的是独立顾问服务，与新版工作簿中的“一站式拓客工具系统”不一致。新版要求首页聚焦微信社群经营、陌生拓客、查找/转发/复制过程、四项价值和十项工具，同时保留既有全栈后台和安全能力。

## 影响范围

- 公开营销路由的全站页头、页脚、移动导航、全局 metadata 和视觉 Token；不覆盖 `/admin`、`/api`、`/health` 或 CMS 管理表面。
- `/`、`/features`、`/team`、`/about`、`/contact`。
- 小程序二维码对话框、移动端说明、资源失败降级和匿名 CTA 分析。
- 集中站点内容模型、路由 metadata、响应式和可访问性测试。

本 FR 分两个 Sprint 交付：M3-02 只建立产品决策页面、小程序体验组件和联系分流，不切换全站 Header/Footer、首页或主导航；这些统一外壳变更由 M3-04 在 `/media` 可访问后完成，避免导航产生断链。

## 需求描述

1. 全站主导航必须为：首页、核心功能、团队解决方案、客来宝媒体、新闻动态、关于我们。
2. 首页必须按统一官网设计呈现：
   - 一站式拓客工具系统定位。
   - 直销人陌生拓客和社群经营问题。
   - 查找、转发、复制三步过程。
   - 持续露脸、精准拓客、团队复制、私域增长四项价值。
   - 四组十项工具和团队方案摘要。
3. `/features` 必须按“曝光→获客→信任→成交→沉淀”说明四组十项工具，不拆十个详情页。
4. `/team` 必须说明团队经验复制、统一品牌、团队小程序、成员归属和交付保障，但不得实现团队管理功能。
5. `/about` 必须使用新版工作簿的公司介绍、企业文化、安全说明、已批准数据、合作伙伴/案例授权状态和联系方式。
6. 全站“免费体验”及首页“立即申请免费体验会员”必须打开客来宝小程序二维码对话框。
7. 二维码对话框必须支持键盘关闭、Escape、焦点进入/恢复、移动端长按说明、有意义的替代文本和 `/contact` 备用链接。
8. 二维码缺失或加载失败时必须显示客来宝产品联系说明，不得切换为客来宝媒体企业微信。
9. `/contact` 必须明确分开“体验 K-Link”和“咨询客来宝媒体”两条路径。
10. 官网不得增加公众登录、账号、Dashboard、客户追踪、数字名片编辑器或团队权限。
11. 小程序二维码为占位资源或状态不是 `production-mini-program` 时，本地 Preview 可以展示明确的测试标识，但 Production 发布状态必须保持 `BLOCKED`，不得用构建成功替代正式资源验证。

## 高层要求

- 复用现有页面、UI、二维码对话框、联系页和匿名分析能力；不新增 UI 框架或状态管理依赖。
- 使用同一客来宝视觉系统，关键视口为 `320px`、`390px`、`768px`、`1440px`。
- 稳定营销页面继续由代码维护，CMS 仍只管理新闻和案例。
- 小程序二维码路径和显示名集中配置；不得在多个页面复制配置值。

## 输入

- `var/客来宝官网文案与结构规划1.0 - 添加修改.xlsx`。
- 正式或测试用客来宝小程序二维码、显示名和打开说明。
- 经授权的产品截图、Logo、案例和统计口径；缺失时使用文字或流程结构说明，不虚构素材。

当前本地工作树未包含上述 `.xlsx` 原始文件；M3-02 与 M3-04 在原始工作簿可用前，以已批准的统一官网设计、当前 SRS、本 FR 和已确认的下游 Sprint 规格中已落定的页面结构、名称与文案为可执行来源。不得据此补写未在这些批准来源中明确的文案、统计口径或素材；缺失细节保持不展示，或只做不冒充真实产品界面的流程/结构说明。M3-02 与 M3-04 完全不实现或展示 `100+`、`10万+`、`99.99%` 及未授权合作 Logo/案例。相关结构化证据和发布许可由 FR-18/M3-05 处理。

## 输出

- 客来宝统一站点外壳。
- 产品首页、核心功能、团队方案、关于和联系页面。
- 无注册的小程序体验 CTA 与可访问降级路径。

## 失败与降级

- 二维码资源失败：移除或隐藏破损图片，以可被辅助技术感知的状态文本显示错误并提供 `/contact`，不得自动提交表单、跳转企业微信或发出企业微信分析事件。
- 产品截图/Logo/案例缺失：隐藏对应展示位或使用不冒充真实界面的结构说明。
- 新页面内容读取异常不得影响 `/admin`、CMS、询盘或健康检查。

## 不纳入范围

- `/media` 页面和旧顾问路由迁移，归 `FR-17`。
- 宣传口径证据、CMS 旧内容清理和全站发布收口，归 `FR-18`。
- Web 登录、公众账号、小程序产品功能和客户数据。
- 十个独立工具详情页。

## 最小验证方式

- 六项主导航的页面、route/metadata 和服务端/standalone smoke 契约覆盖 `/`、`/features`、`/team`、`/media`、`/news`、`/about`；`/news` 至少验证可抓取列表或空状态及 canonical，并回归 `/contact` 分流。
- 小程序对话框测试覆盖打开、关闭、Escape、焦点恢复、二维码失败后图片移除、可访问状态文本、产品备用链接及企业微信语义/事件隔离。
- 品牌/内容测试断言导航、十项工具、四项价值和非范围能力。
- `pnpm test && pnpm lint && pnpm build`。
- 对 `/`、`/features`、`/team`、`/media`、`/news`、`/cases`、`/about`、`/contact` 和政策页执行四个关键视口的紧凑浏览器检查，并抽样验证键盘、Escape、焦点恢复、200% 缩放和 reduced motion。

## 验收要点

- 用户可从首页理解客来宝/K-Link 的受众、过程、价值、工具和团队方案。
- 所有产品体验 CTA 只打开小程序二维码。
- 全站无公众登录和产品后台入口。
- 导航、metadata、页头页脚和移动端路径均使用客来宝主品牌。
- `/features`、`/team`、`/about` 可独立访问且无虚构素材。
