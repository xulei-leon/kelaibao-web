## 1. 文档目的与核心决策

本 SRS 将已批准的客来宝统一官网方向转化为可设计、开发、测试和验收的需求，保留阿里云全栈、询盘、内容发现和安全边界，并以 FR-25 替代旧 CMS 维护方式。

核心决策如下：

1. 客来宝是页头、页脚、metadata、政策、新闻、案例和结构化数据中的唯一主品牌。
2. K-Link 通过官网说明价值、功能和团队方案；免费体验直接展示客来宝小程序二维码，不建立 Web 注册、登录或 Dashboard。
3. 原顾问业务更名为客来宝媒体，只在 `/media` 单页中保留，不形成站中站。
4. “免费体验”与“咨询客来宝媒体”是两个独立入口，分别使用小程序二维码和企业微信二维码。
5. 新闻、获授权案例及其他公开页面均由代码维护；不提供后台内容编辑，更新需构建和部署。
6. 生产运行继续采用 `ESA → Function Compute 全栈 Next.js → RDS MySQL + 私有 OSS`，DirectMail 发送询盘通知。
7. SEO/GEO 只交付可抓取 SSR、metadata、结构化数据、RSS、sitemap 与实验性 `llms.txt` 技术基线，不保证排名、推荐、收录、AI 引用或流量。
8. M2 本地实现状态不等于 Production Live；真实云、备案、授权、口径、成本、恢复和回退证据未齐时必须保持 `BLOCKED`。

## 2. 产品、用户与价值

### 2.1 品牌层级

| 名称 | 对外角色 | 主要使用位置 |
| --- | --- | --- |
| 客来宝 | 网站、公司及整体解决方案主品牌 | 全站外壳、metadata、政策、新闻、案例、关于 |
| K-Link | 一站式拓客工具系统和小程序产品名 | 首页、核心功能、团队方案、免费体验 |
| 客来宝媒体 | 专业表达与内容顾问子业务 | `/media` 与对应企业微信咨询 CTA |

公开页面、邮件、二维码替代文本、结构化数据和发现文件不得继续把旧品牌作为当前品牌。迁移说明、旧内容处理清单、历史评审和证据可以保留明确标注的历史名称。

### 2.2 主要用户

1. 需要持续内容、展示、团队和引流工具的直销从业人员。
2. 需要复制团队经验、统一品牌表达和成员传播机制的团队管理者。
3. 需要专业定位、内容资产和持续推广顾问服务的直销、保险、证券及其他合法专业从业者。
4. 需要了解客来宝公司、产品、媒体服务、新闻和案例的合作方。

### 2.3 核心价值

- **持续露脸：** 用稳定、合规的内容降低重复准备成本。
- **精准拓客：** 通过可转发、可理解的工具和内容支持陌生拓客与社群经营。
- **团队复制：** 将获批准的方法、内容与团队表达形成可重复使用的结构。
- **私域增长：** 支持用户在自身授权和平台规则内维护关系，不承诺好友、客户或成交结果。
- **专业表达：** 客来宝媒体帮助个人从业者建立清晰、可信、可持续的定位和内容资产。

### 2.4 统一边界

网站不得宣称或暗示：

- 保证增加好友、客户、线索、成交、收入、流量、搜索排名、平台推荐或职业结果。
- 提供金融产品推荐、具体保险方案、证券推荐、投资组合、收益预测或个性化专业建议。
- 证明客户具备特定资质，或代表直销企业、保险公司、证券公司、监管机构及其他持牌主体。
- 宣传未经确认的产品功效、收入机会、团队收益、发展下线或快速致富结果。
- 官网自身正在提供 K-Link 产品内的数字名片编辑、客户跟踪、成员管理、访客反馈或私域数据处理能力。

## 3. 产品范围

### 3.1 进入范围

1. 客来宝统一品牌、导航、页面内容、CTA、metadata 和政策。
2. 首页对陌生拓客、社群经营、四项价值、四组十项工具、团队方案和免费体验的说明。
3. `/features` 的曝光、获客、信任、成交、沉淀路径及十项工具说明。
4. `/team` 的团队痛点、赋能体系、团队小程序、成员归属、复制机制和交付保障说明。
5. `/media` 的专业表达与内容顾问定位、服务、适用人群、方法、交付、边界和咨询入口。
6. 客来宝小程序二维码体验、企业微信二维码咨询，以及两个入口各自的可访问降级。
7. 新闻与获授权案例的静态列表、详情、图片及代码发布流程；授权、迁移和内容审查留有仓库记录。
8. 同域 `/api/inquiry` 的最小信息备用询盘，由服务端校验、限频并调用 DirectMail，不保存线索。
9. 公开 SSR、canonical、metadata、Open Graph、JSON-LD、sitemap、RSS 和实验性 `llms.txt`。
10. Privacy、Terms、Disclaimer 及宣传口径登记、授权与 Production 发布门禁。

### 3.2 不进入范围

1. 第二个官网、第二个二级域名、第二个 Next.js 应用、按 Host 切换品牌或独立媒体站。
2. 公众注册、公众登录、客户工作台、团队权限、数字名片编辑器或产品 Dashboard。
3. 在线付款、固定价格、自动报价、订单、发票、CRM、预约、工单或站内聊天。
4. 官网内实现小程序业务、微信 API、自动添加好友、自动发消息、扫码追踪或好友状态同步。
5. 十个工具详情页、`/media/*` 多页面栏目（FR-23 已授权的 `/media/packages` 除外）、新闻/案例或通用页面 CMS、多站点内容模型及 CMS 管理后台。
6. 金融产品展示、保险方案推荐、证券推荐、投资建议或交易撮合。
7. 未经授权的客户姓名、照片、评价、机构 Logo、合作关系、案例或统计数据。
8. 与 `products/sino-en/` 或 `products/geo-agent/` 共享账号、数据、运行时或部署流程。

| `FR-STATIC-001` | 新闻/案例标题、摘要、正文、稳定 slug、日期和图片随仓库维护；更新通过审查、构建、部署，公开请求不查内容库。 |
| `FR-STATIC-002` | 未知 URL 返回 404；曾公开后撤回的 URL 由代码清单返回真实 410；未授权案例或私人草稿不得进入公开清单与制品。 |
| `FR-MEDIASEC-001` | 图片走静态资源构建/交付流程，保留授权、alt、尺寸与预算；不提供 CMS 上传，不擅自改 OSS 权限或删除旧对象。 |
| `FR-HTML-001` | 代码维护受控正文组件；迁入旧 HTML 必须先清理审查，不运行任意脚本、事件或危险 URL，不保留在线 HTML 编辑器。 |
| `FR-PURGE-001` | 缓存刷新归代码发布流程，覆盖变更页面、摘要、发现文件、撤回/跳转路径；失败停止切流或回退，不再依赖 CMS 事务 outbox。 |

### 5.7 首响应 HTML、发现与运行安全

| ID | 需求 |
| --- | --- |
| `FR-SSR-001` | 新闻和案例首个响应必须包含可抓取正文、唯一 title/description、canonical 和正确 JSON-LD。 |
| `FR-DISCOVERY-001` | sitemap、RSS、`llms.txt`、canonical、Open Graph 和 JSON-LD 使用同一静态公开清单，仅含新品牌及有效公开 URL，不查内容数据库。 |
| `FR-DISCOVERY-002` | 发现文件不得包含 `/admin`、`/api`、草稿、下线、未知、私有或旧 canonical URL。 |
| `FR-RUNTIME-001` | API 和健康检查禁止共享缓存；静态新闻、案例与发现文件采用发布版本缓存并精确刷新，不要求 CMS 的 60 秒即时更新。退场前的后台仍禁止共享缓存。 |
| `FR-RUNTIME-002` | 运行时秘密只由 FC 注入，不得进入客户端 bundle、构建制品、日志或版本控制。 |

## 6. 内容与配置模型

稳定营销内容继续集中维护，至少包括：

- 主品牌、K-Link 和客来宝媒体名称与角色。
- 首页价值、十项工具、团队方案、媒体服务和职业边界。
- 小程序与企业微信两个互不替代的二维码配置。
- 页面 metadata、政策摘要、免责声明和匿名分析事件名。
- 联系方式、备案、主体、Logo、案例和数据口径的批准状态。
- 新闻与案例的静态公开清单、稳定 slug、正文、原始发布日期、修改日期、图片、撤回与永久跳转清单；不得把私人草稿或授权证明打包公开。

运行配置必须区分 Preview 与 Production，并对正式域名、二维码、DirectMail、ESA 和实际启用的云资源/秘密执行严格校验。迁移阶段按剩余用途复核 RDS/OSS 与 CMS 配置，不以旧 CMS 必填项作为静态页面读取前提；M5-05 已使健康检查和公开静态内容无需 CMS 配置，FC 模板已移除后台密钥。`SINO_RUNTIME_MODE` 与 `SINO_APP_VERSION` 在 M3-01 中作为既有 M2 内部运行协议兼容保留；它们不得出现在公开品牌文案中，也不得据此创建旧品牌站点或第二 origin。其他历史内部标识只有在改名会改变数据库、Cookie、安全或供应商协议时才可保留，并必须列入受控兼容 allowlist。

## 7. 架构、安全与数据边界

部署平台选型保持不变；以下为迁移期资源边界，新闻与案例的目标请求路径直接读取 FC 制品中的静态内容：

```text
访客
  -> Alibaba Cloud ESA（TLS / CDN / WAF / 限频 / 缓存）
  -> Function Compute（全栈 Next.js：静态公开页面、/api/inquiry）
      -> 构建制品（新闻、案例与发现文件）
      -> RDS MySQL（旧 CMS 数据保留；公开静态内容不查询）
      -> 私有 OSS（既有媒体保留；静态素材按现有交付方案处理）
      -> DirectMail HTTPS API（询盘通知）
```

- 浏览器不得直连 RDS，不得持有数据库、OSS、DirectMail 或阿里云长期凭据。
- migration 只在独立 release step 中执行，使用 MySQL advisory lock，并保持 expand-only/backward-compatible。
- 网站不得保存公众账号、订单、付款状态或询盘线索。
- 静态化保留旧表、migration、修订、审计与媒体以便核对和回退；不擅自 DROP、清库或退役 RDS/OSS。平台配置按剩余实际用途在实施阶段复核。
- `products/sino-en/` 与 `products/geo-agent/` 的源码、数据、构建、部署和工作树必须保持隔离。

## 8. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 可访问性 | 键盘可操作、焦点可见、Dialog 焦点管理正确、语义标题稳定、二维码有替代文本、错误不只依赖颜色 |
| 响应式 | `320px`、`390px`、`768px`、`1440px` 无横向溢出，导航、CTA、Dialog、正文和表单可操作 |
| 性能 | 首屏不依赖重型客户端框架；公开正文服务端输出；媒体尺寸受控 |
| 安全 | 服务端询盘校验、CSRF/来源校验、限频、受控静态正文、媒体权限、秘密隔离与 PII 最小化；CMS 退场前维持旧鉴权 |
| 隐私 | 联系信息与需求不进入 URL、浏览器持久存储、分析、日志或 CMS |
| 可维护性 | 一个应用、一套品牌配置和静态公开清单；不引入 CMS、重复页面或跨应用内容抽象 |
| 可审计性 | 内容变更、部署、撤回、迁移、口径和授权通过代码及发布记录可追溯 |
| 发现能力 | SSR、metadata、JSON-LD、sitemap、RSS、实验性 `llms.txt` 可验证但不承诺结果 |

## 9. 中国大陆上线门禁

以下条件全部具备前，网站最多为 Local/Preview Code Ready，Production 必须保持 `BLOCKED`：

1. 已确认正式主体、域名、ICP备案、隐私与职业表达审查。
2. 已配置并验证正式小程序二维码、企业微信二维码、批准邮箱和 DirectMail 发信身份。
3. 已获得 Logo、产品截图、客户、案例、合作伙伴和统计口径的授权或证明。
4. 真实 ESA、FC、VPC、RDS、OSS、DirectMail 链路、WAF、限频、告警和缓存规则有脱敏证据。
5. RDS 备份恢复、上一应用与新 schema 兼容矩阵、FC 版本回退和 ESA 精确刷新演练通过。
6. 真实规格、流量假设、报价和预算硬上限已确认。
7. 所有 mandatory production gate 均为真实 `PASS`，不得用本地 fake、示例配置、构建成功或占位值替代。

当前真实云与成本输入仍归 `M2-LEGACY-01 / M2-LEGACY-02`，状态保持 `CODE_READY_WITH_EXTERNAL_LEGACY` / Production `BLOCKED`。

## 10. 验收标准

1. 当前仓库根目录为唯一中文官网工程，包名和当前文档使用客来宝语义，不建立第二应用。
2. 公开站只按定义使用“客来宝”“K-Link”“客来宝媒体”，没有旧品牌现态、双站或 `site_key`。
3. 新导航、`/features`、`/team`、`/media`、`/about`、新闻、案例、联系和政策路径完整。
4. 五条旧顾问路由永久重定向到 `/media` 对应区块，`/about` 不重定向。
5. “免费体验”只打开小程序二维码；“咨询客来宝媒体”只打开企业微信二维码。
6. 两个 Dialog 均支持键盘、Escape、焦点恢复、替代文本、错误说明和正确的 `/contact` 降级。
7. 官网没有公众注册、登录、支付、Dashboard、团队权限或产品内客户行为实现。
8. 全站不承诺好友、客户、成交、收入、流量、排名、投资收益或职业结果。
9. 新闻与案例完成 FR-25 静态迁移，CMS 专用入口退场，历史 URL、内容、媒体与授权核对通过，不要求继续保留旧 CMS 功能。
10. `/api/inquiry` 严格校验并调用 DirectMail，不保存线索且日志不含 PII。
11. 新闻、案例首响应 HTML 与 canonical、JSON-LD、sitemap、RSS、`llms.txt` 使用同一静态公开清单，无内容数据库依赖。
12. `products/sino-en/` 与 `products/geo-agent/` 不受修改、引用或构建影响。
13. 完整测试、类型检查、构建、standalone smoke 和本地发布校验通过。
14. Production 状态与真实外部门禁分开报告；缺少任一 mandatory 证据时仍为 `BLOCKED`。

## 11. 测试场景

### 11.1 品牌、路由与内容

- 断言客来宝主品牌、K-Link 产品名、客来宝媒体子业务和六项导航。
- 断言四组十项工具、团队方案、媒体服务与职业边界。
- 断言公开源码、SSR、邮件、metadata 和发现文件没有旧品牌现态、旧 canonical、双 origin 或 `site_key`。
- 断言五条永久重定向目标、锚点与 query 参数行为。

### 11.2 二维码与联系

- 小程序和企业微信分别测试打开、关闭、焦点、替代文本、加载失败和 `/contact` 降级。
- 断言两者不共享配置、资源、事件、标题或失败路径。
- 断言备用询盘的严格字段、隐私同意、honeypot、大小、限频、幂等、超时和零自动重试。

### 11.3 静态内容、迁移与发现

- 验证代码内容的唯一 slug、稳定日期/排序、授权、正文与静态图片，缺少必要字段或清单冲突时构建失败。
- 验证无内容数据库与数据库不可用时页面和发现文件正常，且不查询内容 repository。
- 验证未知 404、历史撤回 410、永久跳转、旧 URL 对照与私人草稿不进入公开制品。
- 验证 CMS 专用入口/API 退场、首响应正文、metadata、JSON-LD 与发现文件同版本，以及部署刷新/回退契约。

### 11.4 发布与隔离

- 在当前仓库根目录运行 `pnpm test`、`pnpm lint`、`pnpm build`、`pnpm smoke:standalone` 和 `pnpm validate:release`。
- 扫描客户端 bundle 和制品，确认没有数据库、管理员、OSS、ESA、DirectMail 或询盘秘密。
- 对比 migrations、schema 相邻实现和 release step，确认品牌迁移未改变 SQL 或协议语义。
- 验证 `products/sino-en/` 和 `products/geo-agent/` 的工作树、submodule 指针与构建入口不变。

## 12. 默认假设与风险

### 12.1 默认假设

1. 客来宝是唯一主品牌，K-Link 是产品名，客来宝媒体是旗下子业务。
2. 官网只介绍并引导体验 K-Link，不实现小程序业务本身。
3. 免费体验使用小程序二维码，媒体咨询使用企业微信二维码，两者正式资产仍受 Production 门禁约束。
4. 全部公开页面由代码维护，不提供新闻/案例 CMS；更新需重新构建和部署。
5. 当前未确认的客户、合作方、Logo、截图、案例或数据不得用占位内容伪装为真实事实。
6. FC、RDS MySQL 与 OSS 的实际规格和总费用以真实门禁证据为准。

### 12.2 主要风险

| 风险 | 控制方式 |
| --- | --- |
| 产品能力被理解为结果保证 | 口径登记、证明门禁、政策和跨页面禁止结果声明 |
| 小程序体验与媒体咨询混淆 | 独立配置、Dialog、CTA、分析事件和失败路径 |
| 客来宝媒体形成站中站 | 共享外壳、Token、Organization、静态内容和联系体系 |
| 旧品牌藏在内容、邮件或发现文件 | 运行输出扫描与逐条代码修订/撤回清单 |
| 静态化遗漏旧内容或 URL | 迁移清单、原路径核对、真实 404/410/跳转和回退验证，保留原数据 |
| 未授权 Logo、截图、案例或数据上线 | 授权/证明登记和 Production mandatory gate |
| 云链路、恢复或回退未验证 | 保持 `BLOCKED`，不得用本地 fake 替代真实证据 |
| 中英文项目互相影响 | 独立目录、依赖、构建、部署、域名和数据，并执行隔离检查 |
