# Sprint M1-02 核心销售与职业场景

> **状态：** draft，待文档 review-confirm；未开始实现。

## 1. Sprint 目标

本 Sprint 覆盖 [FR-02](../1-Requirement/Mainland-Website-FR/FR-02-core-sales-pages-and-service-flow.md) 与 [FR-03](../1-Requirement/Mainland-Website-FR/FR-03-profession-scenarios-and-compliance-boundaries.md)，完成核心销售页面、三个职业场景页和统一的人工定制服务叙事。

核心目标：

- 访问者能理解赛诺全网服务对象、三类服务、方法、流程和边界。
- 直销、保险和证券访问者有独立场景说明及对应禁止表达。
- 全部页面达到 Code/Preview Ready，不把未完成专业审查误写为 Production Ready。

## 2. 前置依赖

- `sprint-m1-01` 已完成全部评审、验证和提交门禁。
- FR-02、FR-03 与本 Sprint 文档 review-confirm 已完成。

协同说明：

- CTA 使用集中配置并先降级到 `/contact`；微信弹层由 M1-03 实现。
- 职业文案的正式专业审查由 M1-05 上线门禁确认。

## 3. 纳入范围

本 Sprint 纳入以下 FR：

- `FR-02` 核心销售页面与定制服务流程。
- `FR-03` 职业场景页与表达边界。

涉及包和目录：

- `src/app/page.tsx`、`services/`、`method/`、`about/`。
- `src/app/for/direct-sales/`、`insurance/`、`securities/`。
- `src/components/` 销售页面组件与 `src/lib/site-content.ts`。
- 内容契约、路由和响应式测试。

## 4. 暂不纳入范围

- 微信二维码弹层、真实表单提交和政策正文。
- 案例页、固定价格、购买、账号或预约能力。
- 正式职业内容审查结论和 Production 发布。

原因：

- 本 Sprint 先形成真实页面与可评审文案；转化、政策和生产门禁在后续 Sprint 收口。

## 5. 工作范围

### 5.1 工作包：核心销售页面

目标：

- 形成“首页 → 服务/方法 → 联系”的完整人工定制服务路径。

实现任务清单：

- [ ] 先写内容与路由失败测试，覆盖品牌、三类服务、合作流程、CTA 和禁止能力。
- [ ] 实现首页首屏、职业入口、服务摘要、人工流程和简明效果声明。
- [ ] 实现 `/services` 的三类服务详情、交付物、限制和人工报价说明。
- [ ] 实现 `/method` 的现状了解、定位、内容、推广规划和复盘过程。
- [ ] 实现 `/about` 的主体占位状态、服务原则和联系路径；禁止虚构主体或资质。
- [ ] 所有 CTA 使用集中配置并以 `/contact` 作为无脚本稳定目标。

测试要求：

- [ ] 页面内容契约覆盖必须出现与禁止出现的口径。
- [ ] 路由、导航与 CTA 无断链。

### 5.2 工作包：职业场景与边界

目标：

- 让三个职业识别适用服务，并防止内容服务被理解为产品推介或专业建议。

实现任务清单：

- [ ] 使用同一职业页面模板和集中 `ProfessionDefinition`，实现三个固定路由。
- [ ] 直销页加入功效、收入机会、团队收益、发展下线和快速致富禁区。
- [ ] 保险页加入产品比较、投保建议、收益演示和机构审核禁区。
- [ ] 证券页加入证券推荐、买卖时点、收益预测、投资组合和个性化建议禁区。
- [ ] 每页说明客户资质、机构规则、素材真实性和最终发布责任。
- [ ] 每页链接预留的 `/disclaimer` 并提供统一微信/联系 CTA。

测试要求：

- [ ] 三个职业固定路由和内容模型映射正确。
- [ ] 禁止用语、责任声明和 disclaimer 链接通过契约测试。

## 6. 验收标准

- 首页、服务、方法、关于和三个职业页全部可访问。
- 三类服务、人工报价和站外交付流程清晰一致。
- 三个职业页分别包含适用场景、禁止范围和客户责任。
- 页面不出现英文站内容、虚构案例、固定价格、支付、账号或效果保证。
- 未完成专业审查时部署只标记 Preview。
