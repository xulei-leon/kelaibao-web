# Sprint M1-04 政策与发布质量

> **状态：** draft，待文档 review-confirm；未开始实现。

## 1. Sprint 目标

本 Sprint 覆盖 [FR-06](../1-Requirement/Mainland-Website-FR/FR-06-policy-privacy-and-claims-boundary.md) 与 [FR-07](../1-Requirement/Mainland-Website-FR/FR-07-metadata-accessibility-and-quality.md)，完成政策页面、全站声明、metadata、抓取、响应式、可访问性和自动化质量收口。

核心目标：

- Privacy、Terms、Disclaimer 与实际线索数据流和产品边界一致。
- 所有公开页面具有正确中文 metadata、canonical、sitemap 与 robots。
- 网站达到 Code/Preview Ready，并明确列出仍需 M1-05 确认的生产信息。

## 2. 前置依赖

- `sprint-m1-03` 已完成全部评审、验证和提交门禁。
- FR-06、FR-07 与本 Sprint 文档 review-confirm 已完成。
- M1-03 已固定表单字段、endpoint 调用方式和匿名分析载荷。

协同说明：

- 政策正文在 Preview 使用明确的待确认字段；生产不得显示占位值。
- 正式专业审查、主体和数据保存信息由 M1-05 门禁确认。

## 3. 纳入范围

本 Sprint 纳入以下 FR：

- `FR-06` 政策、隐私与效果声明边界。
- `FR-07` Metadata、可访问性与发布质量。

涉及包和目录：

- `src/app/privacy/`、`terms/`、`disclaimer/`。
- 全局声明、页脚、表单同意和政策内容配置。
- `metadata`、`sitemap.ts`、`robots.ts`、Open Graph 资源。
- 响应式、可访问性、匿名分析、内容契约与构建输出测试。

## 4. 暂不纳入范围

- 法律意见、备案代办、机构审批或专业审查服务本身。
- 真实主体、正式域名、生产 endpoint、正式企业微信和 Production 发布。
- 付费 SEO、用户画像、行为回放或跨站跟踪。

原因：

- 本 Sprint 完成可评审的产品实现；真实外部信息和正式发布证据在 M1-05 收口。

## 5. 工作范围

### 5.1 工作包：政策与全站边界

目标：

- 让政策页面、简明声明和表单同意形成一致且真实的产品边界。

实现任务清单：

- [ ] 先写政策路由、链接、必须声明和禁止承诺的失败测试。
- [ ] 实现 Privacy：字段、目的、endpoint 接收、共享、保存、用户权利及待确认项。
- [ ] 实现 Terms：人工评估、定制范围、报价、站外合同/付款、第三方平台和客户责任。
- [ ] 实现 Disclaimer：职业资质、机构审核、保险/证券/投资、直销和效果不保证。
- [ ] 连接表单隐私同意、页脚和核心销售页面的简明声明。
- [ ] 建立案例、评价、Logo 和资质必须有书面授权的内容门禁。

测试要求：

- [ ] 政策页面、链接、同意行为、职业边界和禁止承诺通过契约测试。
- [ ] 未确认生产字段被显式列入发布阻塞，而非填充虚假值。

### 5.2 工作包：Metadata、抓取与匿名分析

目标：

- 使公开页面可正确索引，并让 Preview 与 Production 抓取策略分离。

实现任务清单：

- [ ] 为每个公开路由配置唯一中文 title、description、canonical 和 Open Graph。
- [ ] 生成只含真实公开路由的 sitemap；不包含案例、占位或内部预览页面。
- [ ] 非生产默认阻止索引，生产允许核心获客页抓取。
- [ ] 核心文案保持在静态 HTML 中。
- [ ] 匿名分析只记录页面和 CTA 事件，未配置或失败时静默降级。

测试要求：

- [ ] 检查 metadata 唯一性、canonical、sitemap、robots 和静态 HTML。
- [ ] 检查分析事件不含表单字段。

### 5.3 工作包：响应式与可访问性收口

目标：

- 确保移动端、桌面端和键盘用户都能完成咨询路径。

实现任务清单：

- [ ] 检查并修复 320px 以上视口的正文、卡片、二维码、长声明和表单溢出。
- [ ] 检查标题层级、跳过链接、焦点可见性、label、错误关联和 `aria-live`。
- [ ] 对导航、微信 dialog、表单与政策链接建立组件/集成回归。
- [ ] 增加构建输出扫描，阻止英文站内容、禁止能力和虚构证明。

测试要求：

- [ ] 键盘完成首页至微信/表单路径。
- [ ] 在 320px、390px、768px、1440px 完成关键页面人工检查。

## 6. 验收标准

- 三个政策页面公开可访问并与表单及职业边界一致。
- 所有公开页面具有唯一、正确的中文 metadata。
- Preview 阻止索引，Production 配置下 sitemap/robots/canonical 正确。
- 移动端、桌面端和键盘路径均可完成咨询。
- 分析、日志和构建输出不包含询盘个人信息或未授权证明。
- 生产待确认项有明确清单，站点状态仍为 Preview。

## 7. 验证要求

项目声明/推断的验证命令：

- `pnpm test`
- `pnpm lint`
- `pnpm build`

专项验证：

- 扫描所有公开路由的 HTML、metadata、canonical、sitemap 和 robots。
- 执行键盘、320px～1440px 和匿名分析载荷检查。
- 核对政策内容与 M1-03 真实字段及数据流一致。

## 8. 实施顺序

1. 写政策、metadata、抓取和可访问性失败测试。
2. 实现政策页面、简明声明和同意链接。
3. 实现 metadata、sitemap、robots 和匿名分析。
4. 完成响应式、键盘和构建输出收口。
5. 生成 M1-05 所需生产待确认清单。
6. 完成代码 review-confirm、全量验证和独立提交。

## 9. 风险控制

- 政策与真实数据流不一致：政策直接引用已固定字段和配置边界，并在 M1-05 再核对。
- Preview 被搜索引擎收录：非生产环境默认阻止索引。
- 无效的形式化合规：未确认信息保持阻塞，不用模板或猜测内容替代专业审查。
