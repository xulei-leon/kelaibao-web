# Sprint M5-04 文档评审（gpt-5.6-sol）

评审对象：`docs/1-Requirement/Mainland-Website-FR/FR-24-news-cms-authoring.md`、`docs/3-Plan/sprint-m5-04.md`。参考了产品 `AGENTS.md`、`News-CMS-Assessment-and-Enhancement-Design.md` 以及现有内容编辑器、sanitizer、媒体上传服务与 API 契约。范围保持为新闻/案例共享编辑能力补齐，不建议扩展为通用 CMS。

| Severity | Type | Location | Issue | Evidence | Recommendation |
| --- | --- | --- | --- | --- | --- |
| High | Requirement / Reliability | FR-24「失败与降级」；Sprint 5.1、5.2、5.3 | “会话失效要求重新登录并保留当前输入”缺少可实现的交互与 API 契约，尤其上传阶段无法可靠识别会话失效。 | 内容 API 已通过 `contentApiError` 区分 401/403，但现有 `media/presign`、`media/confirm`、`media/public-usage` 路由将认证、CSRF、校验及服务异常统一返回 400 和通用消息。客户端因此无法判断应提示重登、重取 CSRF、重试 confirm 还是停止；若直接跳转登录页，当前 React 表单会丢失。 | 在 Sprint 明确：媒体 API 沿用内容 API 的结构化错误分类（至少 401 `authentication_required`、403 `request_rejected`、可重试 confirm 状态与不可重试校验错误）；收到 401 时禁止导航或重载编辑页，保留组件状态，提示在新标签页或同页非破坏式完成登录后重新取 session/CSRF，再重试原动作。为保存、上传各阶段增加“会话过期但字段、编辑器内容、封面选择仍保留”的行为测试。 |
| High | Correctness / Data loss | FR-24 需求 2、7；Sprint 5.1 | “受支持 HTML 判定”和“无损降级”没有定义可验证的不变量，实施者仍可能在模式切换时用 Tiptap 的解析/序列化结果覆盖原始 `sourceHtml`。 | 现有 sanitizer 允许 `blockquote`、`code/pre`、`table/thead/tbody/tr/th/td` 等标签，而 FR 的最小可视化 schema 只列段落、标题、强调、列表、链接和图片。Tiptap 即使只加载内容，也可能规范化空白、属性和标签结构；当前文档没有规定何时可进入可视化模式、切换未编辑时应提交哪份值、失败时如何回滚。 | 增加明确算法：原始 `sourceHtml` 始终单独保存；先在服务端安全解析并返回“可视化兼容”结果，原始 HTML 不进入活动 DOM；不兼容即锁定源码模式。兼容内容进入可视化后，只有发生真实编辑才生成候选 HTML；切回源码前先做受控序列化与保真检查，失败则保留原值并阻止切换。定义规范化比较规则，并用 sanitizer 全部允许标签、属性、空白、旧内容和未知标签建立往返测试语料。 |
| High | Security | FR-24 需求 1、2；Sprint 5.1 | 文档限制了图片来源，却没有规定可视化编辑器中链接的实时安全行为；服务端保存时净化不能防止编辑态中的主动导航。 | 现有 sanitizer 只在预览/保存时把链接限制为 `https`/`mailto` 并补 `rel`。Tiptap 会在管理页 DOM 中渲染 link node；若源码导入、粘贴或链接对话框允许危险协议，管理员在保存前即可与该链接交互。Sprint 只明确“安全且已认可的图片 URL”和“不注入原始 HTML”，未覆盖链接协议、点击行为及粘贴链接。 | 在 Sprint 5.1 增加链接契约：仅接受绝对 `https:` 与经过校验的 `mailto:`，拒绝协议相对 URL、凭据型 URL 和危险协议；编辑态 `openOnClick: false`，外链最终输出继续由服务端 sanitizer 决定；源码进入可视化前必须使用服务端安全结果。增加链接创建、粘贴、旧 HTML 导入与点击不导航测试。 |
| Medium | Reliability / API contract | FR-24 需求 4；Sprint 5.2 | “confirm 最多 3 次、固定有界退避”不足以定义正确重试；现有服务端租约和响应形态会把仍在处理、永久校验失败和临时故障混为一类。 | `confirmMediaUpload` 的确认租约为 2 分钟，首次请求需要检查 pending 对象、复制、再次下载并校验；客户端超时后同 intent 的后续请求可能得到 “already in progress”。当前 confirm 路由把该状态及其他异常全部映射为 HTTP 400。三次固定重试可能在租约内全部耗尽，也可能无意义地重试文件校验失败。 | 规定每阶段超时和 `AbortController` 行为，并为 confirm 定义可枚举状态：已确认直接返回同一 asset；处理中返回可重试状态并给出 `Retry-After` 或明确轮询间隔；临时 OSS/网络错误可重试；过期、校验失败不可重试并要求重新选择/上传。退避总时长应覆盖服务端确认窗口或由服务端状态驱动；测试“首次响应丢失但服务端最终成功”和“长期处理中后恢复”。 |
| Medium | Clarity / API contract | FR-24 需求 5；Sprint 5.2 | 新增 `GET /api/admin/media/[id]` 的 DTO 没有列出字段及 URL 生成规则，封面重开回显实现会出现分歧。 | 需求只称“公开元数据”，Sprint 又要求不因读取封面而依赖未过期 STS。现有 confirm 响应含整个 asset 展开值及 `publicUrl`，其中包含 object key、校验和、创建人等并非回显所需字段；若 GET 复用 `resolveOssStsConfig()`，STS 过期会让已保存封面无法显示。 | 在文档固定最小 DTO：`id`、由 `OSS_ASSETS_BASE_URL + confirmed object key` 服务端生成的 `publicUrl`、`mimeType`、`byteSize`、`width`、`height`、`publicUsageConfirmedAt`；不返回 `objectKey`、checksum、createdBy、pending/intent 信息。读取路径只解析独立 assets-origin 配置并查询已确认 asset，响应设 `Cache-Control: private, no-store`，404 与 401/403 使用结构化错误。 |
| Medium | Usability / Requirement | FR-24 需求 3、6；Sprint 5.2 | 通用上传上限 10 MB 与封面强约束（≤350 KB、至少 1200×630、约 1.90:1）之间缺少角色化前置校验，可能完成昂贵上传和公开使用确认后才在保存时失败。 | 现有 presign/confirm 接受不超过 10 MB 的三种图片并建立 media asset；封面规格只在内容 repository 绑定 revision 时校验。FR 要求封面上传后自动绑定且展示尺寸/体积，但未明确何时阻止不合规资产成为封面。 | 共享上传函数保留 10 MB 通用限制；封面控件在 presign 前读取尺寸并检查 350 KB、最小尺寸和宽高比，在 confirm 返回后再以服务端元数据复核，未通过则不绑定且不显示“可保存”状态。服务端现有 repository 校验继续作为最终边界。正文图片不套用封面规格，避免扩大限制。 |
| Medium | Feasibility / Dependency | Sprint 3、5.1、7 | 新增 Tiptap 依赖已进入范围，但缺少兼容性与客户端加载门禁，可能在 Next.js 15/React 19 的管理页面引入 SSR/hydration 或包体问题。 | `package.json` 当前使用 Next.js 15.5、React 19.1，尚无 Tiptap 依赖；现状核查文档明确要求实施前核对版本、许可、React 19/Next.js 15 兼容性、包体与 HTML 往返保真，FR/Sprint 未把这些核对转成任务或验收证据。 | 在 Sprint 5.1/5.3 增加依赖门禁：锁定具体 Tiptap 核心与 extension 版本及许可，确认 React 19 支持；编辑器仅在管理端客户端边界加载，验证首次 SSR/水合无告警和无浏览器全局访问错误；记录构建产物增量。若不满足门禁，降级为源码编辑加受限格式辅助，不引入另一套内容模型。 |
