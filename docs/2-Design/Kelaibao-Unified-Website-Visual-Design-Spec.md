## V3.3 视觉覆盖

- Header 导航为“首页｜核心工具｜团队方案｜媒体服务｜新闻动态｜关于我们”。
- `/features` 的九项权益使用语义表格，并在窄屏保持可读、可横向查看且页面本身不产生横向溢出。
- `/media/packages` 复用统一站点外壳、媒体深色 Hero、响应式套餐卡和企业微信 CTA；标准价与会员价必须同时可读，不设计购买或结算控件。

## M4-04 视觉覆盖

- 主色 Token 以 `#094092` 为基准，辅色以 `#3f6cc4` 为基准；媒体咨询、错误、正文、hover、active 与 focus-visible 继续使用独立语义 Token。
- Header 使用客来宝/K-Link 候选 Logo，说明为“K-Link 一站式拓客工具系统”；导航文字为黑色，栏目名采用“媒体中心”和“新闻中心”。
- Footer 标语为“内容赋能 资源链接 商机互联”，政策入口采用 M4-04 五项显示名。
- 首页、功能和团队页删除独立边界卡后，等义限制必须贴近 Hero、能力或 CTA，并保持 Footer/政策可达。
- 媒体痛点卡使用四个语义图标及响应式列表；“百家主流媒体全覆盖”下的可见名称必须标为部分示例，并保持 Production blocker。
- 关于页采用短 Hero + 独立窄栏四段公司介绍；办公室与到访图片使用原生 Dialog、键盘/Escape/焦点恢复和普通链接降级。

## 1. 设计目标与原则

### 1.1 体验目标

1. 首屏在 5 秒内说明客来宝、K-Link 的用途、核心价值和“免费体验”下一步。
2. 用户能沿“理解问题 → 查看功能 → 判断团队适配 → 免费体验”完成产品决策。
3. 需要顾问服务的用户能进入 `/media`，清楚理解客来宝媒体与 K-Link 的区别。
4. 小程序体验和企业微信咨询具有不同名称、图标语义、说明、Dialog 与失败路径。
5. 公开口径、职业限制、隐私和授权状态可读，不通过小字号或折叠弱化。
6. 移动端、微信内置浏览器和桌面端均保持稳定导航、可触达 CTA 和无横向溢出。

### 1.2 设计原则

- **产品信息优先：** 科技感来自网格、流程、信息关系和真实界面结构，不来自霓虹、代码雨或装饰性大屏。
- **主品牌唯一：** 客来宝拥有站点外壳；K-Link 和客来宝媒体不得拥有竞争性 Logo、导航或主题。
- **行动语义明确：** 全站产品主 CTA 是“免费体验”；媒体局部 CTA 是“咨询客来宝媒体”。
- **真实材料优先：** 缺少已授权截图、照片、Logo、案例或数据时，用文字、流程和结构表达，不制作虚构素材。
- **边界可见：** 不以视觉暗示保证好友、客户、成交、收入、流量、排名或职业结果。
- **无障碍内建：** 颜色不作为唯一状态，键盘、焦点、语义标题、替代文本和 reduced motion 是组件契约。

### 1.3 非目标

- 不设计公众账号、Web 登录、SaaS Dashboard、支付、CRM、在线预约或团队管理界面；仅允许 V3.3 `/media/packages` 咨询报价卡。
- 不建立第二套媒体站视觉、双二级域名或按 Host 切换品牌。
- 不把十项工具拆成十个独立详情模板。
- 不使用未经授权的人物、产品截图、客户评价、合作 Logo、证书、数据或成功案例。
- 不使用英文站品牌、图片、组件或设计资产。

## 2. 品牌层级与命名

| 名称 | 视觉角色 | 使用规则 |
| --- | --- | --- |
| 客来宝 | 唯一主品牌 | Wordmark、页头、页脚、metadata、政策、新闻、案例、关于 |
| K-Link | 产品名 | 首页、功能、团队和小程序体验说明；不单独建立站点外壳 |
| 客来宝媒体 | 子业务名 | `/media` 标题与企业微信 CTA；不建立独立 Logo、主题或 Organization |

- 未交付正式 Logo 时，页头使用高质量“客来宝”文字标识，不制作临时复杂图标。
- 产品名与主品牌同屏时使用“客来宝 K-Link”或上下级清晰的排版，不把 K-Link 放大成站点主品牌。
- 客来宝媒体的顾问式气质通过内容密度、章节节奏和版式表达，不通过新色板或独立导航表达。
- 迁移背景、内容处理清单和历史证据可以出现旧名称；当前公开 UI 不得出现旧品牌现态。

## 3. 色彩系统

### 3.1 核心 Token

| Token | 色值 | 角色 | 使用要求 |
| --- | --- | --- | --- |
| `brand` | `#102A56` | 客来宝主色 | 标题、深色区、页脚、关键结构，不作为大段正文背景连续铺满 |
| `action` | `#2563EB` | 产品主行动色 | “免费体验”、关键链接、选中态和焦点关联元素 |
| `canvas` | `#F5F8FC` | 页面浅背景 | 默认页面底色与宽区块背景 |
| `surface` | `#FFFFFF` | 内容表面 | 卡片、Dialog、表单、导航和内容面板 |
| `line` | `#CBD7E8` | 边框与关系线 | 网格、卡片、表格、分隔线和流程连接 |
| `text` | `#10233F` | 正文主色 | 标题之外的主要文本 |
| `muted` | `#52657D` | 次级文字 | metadata、帮助文字和非关键说明 |
| `wechat` | `#0F6B50` | 媒体咨询语义 | 仅用于企业微信 CTA、成功状态或明确微信语义 |
| `danger` | `#A33A32` | 风险与错误 | 错误、禁止和高风险提示，不作装饰 |

补充颜色：

- 深色正文反白：`#F8FBFF`。
- 深色区次级文字：`#C8D5E8`。
- Action hover：`#1D4ED8`。
- 浅色 hover：`#EAF1FA`。
- 焦点环：`#2563EB`，必须同时具备轮廓和偏移。

### 3.2 使用边界

1. `action` 是全站产品主 CTA 色，不使用企业微信绿替代“免费体验”。
2. `wechat` 只用于 `/media` 或联系页中明确的企业微信咨询，不扩展为第二品牌色。
3. 每个页面最多一个连续大面积 `brand` 深色区，页脚除外。
4. 风险、成功、禁用和选择状态必须同时使用文字、图标、边框或形态，不能只依赖颜色。
5. 正文、按钮、链接和表单状态必须达到 WCAG AA 对比度。

### 3.3 CSS Token 示例

```css
:root {
  --color-brand: #102a56;
  --color-action: #2563eb;
  --color-canvas: #f5f8fc;
  --color-surface: #ffffff;
  --color-line: #cbd7e8;
  --color-text: #10233f;
  --color-muted: #52657d;
  --color-wechat: #0f6b50;
  --color-danger: #a33a32;
}
```

## 4. 字体、网格与形态

### 4.1 字体与层级

- 使用系统中文无衬线字体栈，优先保证大陆设备和微信内置浏览器的稳定显示。
- H1 桌面建议 `48–64px`，移动端 `34–42px`；行高约 `1.08–1.2`。
- H2 桌面建议 `32–42px`，移动端 `26–32px`；正文 `16–18px`，行高 `1.65–1.8`。
- Eyebrow、数据标签和 metadata 不小于 `12px`；政策、风险与免责声明正文不小于 `14px`。
- 中文段落控制行长；桌面正文列约 `640–760px`，产品说明宽列不超过 `1120–1200px`。

### 4.2 网格与间距

- 桌面使用 12 列网格，最大内容宽度约 `1200px`；平板 8 列，移动 4 列。
- 页面水平留白：桌面 `32–48px`，平板 `24–32px`，移动 `16–20px`。
- 区块垂直间距：桌面 `80–120px`，移动 `56–80px`。
- 使用 `4/8px` 间距基线；组件内部间距优先 `8/12/16/24/32px`。

### 4.3 形态与图形

- 卡片使用 `8–12px` 圆角、`1px` 边框和轻量阴影；不使用厚重玻璃拟态或大面积渐变。
- 产品流程使用清晰线条、编号、节点和方向；不得伪装成真实数据 Dashboard。
- 图标使用简洁线性风格，必须配合可理解文字，不承担唯一语义。
- 没有真实截图时使用标注为“结构说明”的界面骨架或流程关系，不制作虚假产品截图。

## 5. 全局组件

### 5.1 Header

- 桌面高度约 `72px`，使用白色或半透明白色表面及 `1px` 底部分隔线。
- 左侧为“客来宝”Wordmark；主导航固定为：首页、核心功能、团队解决方案、客来宝媒体、新闻动态、关于我们。
- 最右为蓝色“免费体验”按钮，打开小程序 Dialog。
- 当前页面使用文字权重、下划线或背景层级标记，不使用整块第二品牌色。
- 移动端保持同一 IA；菜单按钮和所有链接触控尺寸不少于 `44×44px`。

### 5.2 Footer

- 使用 `brand` 深色背景与反白文字，包含客来宝说明、主导航、新闻/案例、政策和联系入口。
- 可以同时提供“免费体验”和普通联系链接，但不得把客来宝媒体表现为独立站点。
- 不展示登录、价格、支付、合作 Logo、统计数字或未经确认的备案信息。

### 5.3 CTA

#### `product-primary`

- `action` 蓝背景、白色文字、`48–52px` 高度、`8px` 左右圆角。
- 文案使用“免费体验”或明确的 K-Link 体验语义，激活后打开小程序 Dialog。

#### `media-wechat`

- `wechat` 绿背景、白色文字，只用于“咨询客来宝媒体”等明确企业微信语义。
- 不得用于 K-Link 登录、试用或产品降级。

#### `secondary` 与 `text-link`

- 次级按钮使用透明/白色背景、主色边框和文字；文本链接使用主色与清晰下划线或箭头。
- 一个视区最多一个同等权重的主 CTA；辅助动作不得伪装为第二个主行动。

### 5.4 Dialog

小程序与企业微信可以复用可访问 Dialog 原语，但内容契约必须独立：

| 属性 | 小程序体验 | 客来宝媒体咨询 |
| --- | --- | --- |
| 标题 | 体验 K-Link | 咨询客来宝媒体 |
| 资源 | 客来宝小程序二维码 | 企业微信二维码 |
| 主色 | `action` | `wechat` |
| 说明 | 扫码进入小程序申请体验 | 扫码发起顾问服务咨询 |
| 失败降级 | `/contact` 产品体验区 | `/contact` 媒体咨询区/备用询盘 |

- Dialog 提供关闭按钮、焦点进入与恢复、Escape 关闭、遮罩关闭规则和可读错误。
- 二维码有效显示尺寸不小于 `220×220px`，保留白边，不加纹理、水印或装饰覆盖。
- 移动端提供长按识别或保存说明；图片必须有与入口匹配的替代文本。
- 加载失败时隐藏破损图片，不得让一种二维码替代另一种二维码。

### 5.5 表单与政策正文

- 备用询盘表单默认单列，Label 永久可见，控件最小高度 `48px`；错误、成功、超时和未配置状态均提供文本。
- 表单只属于人工咨询降级，不作为小程序免费体验的前置步骤。
- 政策正文最大宽度 `720–760px`，H2/H3、列表、表格和链接保持清晰层级。
- 政策页面不加入营销大图、虚构证明或粘性主 CTA；页面末尾提供普通导航和联系入口。

## 6. 页面设计

### 6.1 首页 `/`

首页按以下顺序组织：

1. 客来宝 K-Link“一站式拓客工具系统”首屏、陌生拓客问题和“免费体验”。
2. 工具登录即可使用的说明，以及进入陌生拓客场景的方式。
3. 查找、转发、复制三步社群经营过程。
4. 持续露脸、精准拓客、团队复制、私域增长四项价值。
5. 内容、展示、团队、引流四组工具摘要。
6. 团队方案摘要、客来宝媒体、新闻和案例摘要。
7. 最终小程序二维码 CTA 与不保证结果的边界。

Hero 桌面建议 `7 + 5` 列：左侧标题、说明、主/次 CTA 和边界；右侧使用工具关系、流程或获批准截图。移动端改为单列，主 CTA 在首屏可见。

### 6.2 核心功能 `/features`

- 用“曝光 → 获客 → 信任 → 成交 → 沉淀”建立页面主线。
- 展示四组十项工具：内容工具（今日热点、每日健康、未来周报、商业洞察）、展示工具（数字名片、推广海报）、团队工具（品牌专刊、团队小程序）、引流工具（资源集市、人脉社群圈）。
- 每项工具至少说明用途、适用场景和边界；首版不建立工具详情页。
- 产品能力与官网能力必须视觉上可区分，不展示伪造的实时数据、访客数或客户列表。

### 6.3 团队方案 `/team`

- 按团队经验难复制、品牌传播不统一、成员留存和管理信息不足组织问题。
- 说明品牌专刊、团队小程序、成员分享归属、访客反馈和三类交付保障。
- 使用关系图、步骤或角色卡说明团队机制，不制作真实后台或成员数据假图。
- 页面只介绍方案并引导体验/咨询，不提供团队登录、权限或数据操作。

### 6.4 客来宝媒体 `/media`

- 页面首屏明确“客来宝旗下专业表达与内容顾问业务”。
- 依次覆盖专业定位与个人形象、内容资产、持续推广顾问、适用人群、五步方法、代表性交付、适合/不适合情形和职业边界。
- 使用同一 Header、Footer、字体、Token 与组件；可降低卡片密度、增加正文宽度控制和章节编号，形成顾问式阅读节奏。
- 唯一局部主 CTA 为“咨询客来宝媒体”，打开企业微信 Dialog。
- `services`、`direct-sales`、`insurance`、`securities`、`method` 锚点必须有稳定标题和滚动定位余量。

### 6.5 新闻、案例、关于与联系

- 新闻与案例列表/详情优先正文可读性、发布日期、类型、授权状态和清晰返回路径；不使用虚构缩略图填充。
- `/about` 说明客来宝公司、文化、批准数据、安全原则、合作伙伴与联系方式；未确认内容显示诚实状态或不展示。
- `/contact` 上半部分明确区分 K-Link 小程序体验与客来宝媒体企业微信咨询，避免同一二维码或同一按钮兼任两种语义。
- 二维码失败、DirectMail 未配置和表单错误均提供不会误导的下一步。

### 6.6 Privacy、Terms、Disclaimer

- 统一使用窄正文列和稳定目录，覆盖官网、K-Link 产品说明和客来宝媒体顾问服务。
- 宣传口径、职业责任、隐私最小化和第三方平台限制需要醒目但不戏剧化。
- 不使用 Hero 大图、人物照、销售卡片或粘性二维码行动条。

## 7. 响应式与交互

| 视口 | 重点检查 |
| --- | --- |
| `1440px` | 12 列布局、Hero 比例、标题不超过合理行数、主 CTA 和右侧结构同屏 |
| `768px` | 导航折叠、卡片重排、流程转为双列/纵向、Dialog 不溢出 |
| `390px` | 单列、触控目标、二维码宽度、表单和政策正文可读 |
| `320px` | 无横向溢出、长中文/英文/数字可换行、Dialog 和菜单可关闭 |

- 交互时长以 `120–240ms` 为主，只使用 opacity、transform、颜色和轻量高度变化。
- `prefers-reduced-motion: reduce` 时关闭非必要位移、滚动和装饰动效。
- Sticky Header 不遮挡锚点标题；`/media#...` 使用合适的 `scroll-margin-top`。
- 200% 缩放时内容可重排，不出现被裁切的导航、Dialog、正文或 CTA。

## 8. 可访问性基线

1. 每页一个清晰 H1，H2/H3 不跳级，导航和 Dialog 使用正确语义。
2. 所有交互元素可通过键盘访问，焦点环明显，Dialog 关闭后焦点返回触发器。
3. 菜单、按钮、二维码和表单触控目标不小于 `44×44px`。
4. 小程序与企业微信二维码具有不同且准确的替代文本。
5. 错误、成功、禁用、选中和风险不能只依赖颜色。
6. 对比度、缩放、reduced motion、屏幕阅读器名称与状态更新纳入验收。

## 9. 设计到代码映射

- 全局 Token 位于统一样式层；组件不得内嵌第二套媒体主题。
- Header、Footer、Section、ActionLink、PageHero、Dialog 和内容卡片优先复用现有 UI 原语。
- 小程序与企业微信复用可访问行为，但配置、文案、资源、事件与失败状态分别建模。
- 页面级内容集中维护，避免在 Header、Footer、页面和 metadata 中重复写品牌名与二维码配置。
- News/Case 的 CMS HTML 必须使用允许的正文样式，不得绕过 sanitizer 注入页面级脚本或主题。

## 10. 视觉 QA 与验收

### 10.1 自动检查

- 断言六项主导航、客来宝 Wordmark、蓝色免费体验语义和页面 H1。
- 断言小程序/企业微信 Dialog 的名称、替代文本、资源、事件和降级互不混用。
- 断言 `/features` 十项工具、`/team` 核心内容、`/media` 锚点和旧路由重定向。
- 断言公开 UI、metadata、邮件和发现文件不把旧品牌作为现态。
- 断言无公众登录、支付、价格、Dashboard、`site_key` 或第二品牌外壳。

### 10.2 人工检查

对 `/`、`/features`、`/team`、`/media`、`/news`、`/cases`、`/about`、`/contact` 和政策页检查：

1. `320px`、`390px`、`768px`、`1440px` 无横向溢出。
2. 导航、CTA、锚点、Dialog、二维码、表单和错误状态可操作。
3. 键盘顺序、Escape、焦点恢复、200% 缩放和 reduced motion 正确。
4. 小程序体验与媒体咨询的颜色、文案和下一步不会混淆。
5. 未授权素材、占位数据、绝对效果声明和职业风险没有被视觉弱化。

### 10.3 品牌与内容检查

- 客来宝始终是唯一站点主品牌。
- K-Link 被理解为产品，不被理解为第二网站。
- 客来宝媒体被理解为旗下顾问业务，不形成站中站。
- 视觉呈现为可信的产品科技官网，而不是金融销售站、AI 工具站、奢侈品会所或虚构数据 Dashboard。
- Production 未通过时，不通过“正式上线”“稳定保障”等视觉标识暗示外部门禁已完成。

## 11. 实施顺序

1. M3-01：迁移目录、主品牌、文档名和统一 Token，不改变页面行为或 M2 协议。
2. M3-02：实现 `/features`、`/team`、`/about`、小程序配置和联系分流。
3. M3-03：实现 `/media`、企业微信语义和旧路由永久重定向。
4. M3-04：切换统一 Header/Footer、首页和全站免费体验入口。
5. M3-05：收口政策、口径、CMS 内容、邮件、发现文件与发布门禁。

每个阶段都复用 M2 安全、CMS、DirectMail、SSR 和发布能力；真实云、授权、备案、口径与恢复证据未齐时 Production 保持 `BLOCKED`。
