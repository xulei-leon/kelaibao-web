## 1. 本轮设计原则

### 1.1 唯一目标

把当前“结构完整但视觉朴素”的网站升级为成熟、可信、有产品感的互联网服务企业官网，同时确保既有功能和内容不受影响。

### 1.2 必须保持不变

本轮是纯视觉升级，以下内容全部冻结：

- 路由、页面数量和主导航顺序。
- 每个页面现有 Section 数量、模块顺序和信息层级。
- Hero、内容区、卡片区、流程区和最终 CTA 的现有栅格关系。
- 所有 H1、H2、H3、正文、列表、边界说明和 CTA 文案。
- K-Link 小程序与客来宝媒体企业微信两套独立入口。
- 二维码 Dialog、移动菜单、表单、CMS、SSR、SEO/GEO 和分析行为。
- 当前响应式断点和 `320px`、`390px`、`768px`、`1440px` 验收范围。

### 1.3 允许调整

只允许调整不会改变整体 layout 与文字内容的表现层：

- 颜色、字体权重、字号微调、行高、字距和文本颜色。
- 背景、边框、圆角、阴影、分隔线和装饰纹理。
- 按钮、卡片、流程节点、结构示意和二维码容器的视觉样式。
- Header、Footer、Hero 和各 Section 的视觉层次。
- Hover、focus、进入动画及 `prefers-reduced-motion` 降级。
- 为现有元素增加样式类或页面级视觉变体，但不得改变 DOM 内容顺序。

### 1.4 禁止事项

- 不新增、删除、合并或移动页面模块。
- 不改写、缩写、扩写或重新排序现有文案。
- 不增加价格、客户 Logo、评价、统计数据、Dashboard 或新的 CTA。
- 不将参考网站的页面布局直接套用到客来宝。
- 不引入保健品商城、商品陈列、购物车、功效宣传或直销机会站风格。
- 不把 K-Link、客来宝媒体或 GEO 设计成第二主品牌。

## 2. 当前实现审阅

### 2.1 已有基础

当前代码已经具备完整的设计骨架：

- `SiteHeader`、`SiteFooter` 和 `PublicAppShell` 已统一公开站外壳。
- `PageHero`、`Section`、CTA、Dialog 和内容卡片已有复用基础。
- 首页、功能、团队、媒体和关于页已按内容规格实现。
- 蓝色产品 CTA 与绿色媒体咨询 CTA 已完成语义区分。
- 桌面和移动端无横向溢出，菜单、键盘焦点和二维码流程可用。
- 色彩 Token、间距和主要响应式规则已经存在。

### 2.2 视觉问题

在 `2026-08-02` 对当前开发站桌面与移动端进行检查后，确认主要问题属于视觉表现，而不是信息架构：

本节为设计判断，不替代可复核基线。浏览器版本、构建/commit、路由、视口和 before 截图将在 WP0 固化到 `docs/5-Evidence/m4-02/README.md`；若正式基线与本节判断不一致，以 WP0 证据为准并先更新文档门禁。

1. **页面辨识度低。** 首页、功能、团队和媒体页大量复用相同浅色网格 Hero，页面气质过于接近。
2. **产品感不足。** 当前视觉主要由文字、细边框和结构占位组成，难以形成成熟 SaaS 官网的产品印象。
3. **模块节奏单一。** 多个 Section 连续使用同类标题、卡片和边框，长页面阅读节奏偏平。
4. **层级偏硬。** `4px` 圆角、较弱阴影和大量直角分隔使页面更像结构原型，而非正式品牌网站。
5. **首屏焦点分散。** 首页左侧产品价值和右侧问题卡权重接近，主标题、CTA 与辅助信息缺少明确的视觉主次。
6. **移动端首屏偏长。** 当前首页 Hero 在窄屏包含标题、说明、CTA 和完整问句卡，首屏信息密度和高度较高。
7. **样式维护成本高。** `globals.css` 已累积多轮页面样式，后续换肤需要先建立清晰的覆盖层和组件视觉契约。

### 2.3 本轮处理方式

不通过调整模块或删除内容解决上述问题，而通过以下方式改善：

- 强化文字、色块、边框和阴影的视觉主次。
- 让同一布局在不同页面拥有不同但同源的视觉主题。
- 使用背景带、表面层和留白节奏区分相邻 Section。
- 将现有结构示意、编号、流程和卡片提升为正式产品视觉语言。
- 在移动端通过字体、间距和卡片密度调整缩短感知长度，不改变模块顺序。

## 3. 参考风格与转化规则

### 3.1 Mindbody：全站 SaaS 产品感

参考地址：<https://www.mindbodyonline.com/business>

只借鉴以下风格特征：

- 大字号、短行宽、明确主次的产品标题。
- 充足但不空洞的留白，以及轻盈的表面层。
- 产品能力通过精致界面框、流程和局部色块呈现。
- 主 CTA 稳定醒目，次级动作克制。
- 健康服务行业的友好、可信与现代感。

转化到客来宝：

- 保留当前 Hero 布局，仅增强左侧标题与 CTA 的视觉主导权。
- 将当前结构示意、功能占位和工具卡处理成精致的 SaaS 产品框架。
- 使用柔和阴影、适度圆角和冷色背景提升正式产品感。
- 不复制 Mindbody 的图片、紫色体系、页面结构或商业文案。

### 3.2 HubSpot：主品牌统一与模块系统

参考地址：<https://www.hubspot.com/>

只借鉴以下风格特征：

- 单一主品牌统领产品、解决方案、服务和内容。
- 页面模块丰富但组件语言统一。
- 清晰的实色 CTA、友好的圆角和高识别度 Section 色带。
- 数据、流程、内容与服务使用不同视觉容器，但保持同一设计系统。
- 长页面通过背景色和模块密度变化形成节奏。

转化到客来宝：

- 客来宝继续是 Header、Footer 和全站视觉主体。
- K-Link 与客来宝媒体不新增 Logo、独立字体或独立导航。
- 保留当前 Section 顺序，通过白、冷浅蓝、深蓝三种背景节奏增强层次。
- 统一按钮、卡片、流程节点、编号、链接箭头和表面阴影。
- 不复制 HubSpot 的橙色、插画、导航结构或组件布局。

### 3.3 Profound：客来宝媒体的局部科技气质

参考地址：<https://www.tryprofound.com/>

只在 `/media` 借鉴以下风格特征：

- 深色、高对比的科技与信息可信感。
- 细线网格、数据关系线和克制的冷色光感。
- 简洁、锐利的标题与更专业的编辑式信息密度。
- 对 AI 搜索、公开信息和品牌可见性的现代视觉联想。

转化到客来宝媒体：

- 不改变 `/media` 当前九个 Section 的顺序、文字或栅格。
- Hero 从全站浅色基线转为深海军蓝主题，仍使用现有标题、说明和绿色咨询 CTA。
- 现有流程、核心价值、内容支柱和媒体范围采用更精细的线框、编号和数据关系视觉。
- 深色主题只用于 Hero、一个重点过渡区和最终 CTA；正文仍以白色或冷浅色表面保证可读性。
- GEO/AEO 只作为视觉气质来源，不新增 GEO 产品、评分、Dashboard 或结果承诺。
- 不复制 Profound 的黑色整站、荧光色、动画、文案或产品界面。

## 4. 全站视觉系统

### 4.1 色彩

保持现有品牌色语义，只优化比例与层次：

| 角色 | 色值 | 使用规则 |
| --- | --- | --- |
| 主品牌深蓝 | `#102A56` | 标题、Footer、深色重点区和结构节点 |
| 深蓝提升层 | `#173A70` | Hover、深色卡片和媒体页层次 |
| 产品行动蓝 | `#2563EB` | “免费体验”及产品相关关键交互 |
| 产品 Hover | `#1D4ED8` | 蓝色 CTA Hover |
| 媒体咨询绿 | `#0F6B50` | 仅用于客来宝媒体企业微信咨询 |
| 页面冷背景 | `#F5F8FC` | 默认画布和浅色区块 |
| 内容白 | `#FFFFFF` | 卡片、表面、Header 和 Dialog |
| 关系线 | `#CBD7E8` | 边框、流程线和结构分隔 |
| 辅助文字 | `#52657D` | 正文辅助信息和说明 |
| 克制金色 | 复用现有 `--champagne`（当前 `#C6A15B`） | 当前页下划线、编号和极少量编辑装饰；不得作为 CTA、状态色或第二品牌色 |

比例建议：

- 白色与冷浅色占全站约 `75%–82%`。
- 深蓝占约 `12%–18%`，用于 Header 文字、重点区和 Footer。
- 产品蓝、媒体绿与金色合计不超过 `8%`。
- 不新增 HubSpot 橙、Mindbody 紫或 Profound 荧光色。

### 4.2 字体

- 全站继续使用现有中文无衬线字体栈。
- H1 保持现有文字与换行逻辑，桌面建议 `52–60px`，移动端 `34–40px`。
- H2 桌面 `34–42px`，移动端 `27–32px`。
- 正文 `16–18px`，行高 `1.7–1.85`。
- 数字编号与微标签使用无衬线大写/数字风格，不新增装饰性英文。
- `/media` 的引语或重点句可继续使用现有衬线字体，但正文和控件不切换字体。

### 4.3 圆角、边框与阴影

| 元素 | 视觉规格 |
| --- | --- |
| 主按钮 | `8px` 圆角，实色，无渐变 |
| 内容卡片 | `10–12px` 圆角，`1px` 冷灰边框 |
| 大型结构面板 | `12–16px` 圆角，轻量分层阴影 |
| Dialog | `12px` 圆角，保持现有可访问行为 |
| 阴影 | 只用于浮层、Hero 视觉和重点卡片，不给所有卡片统一加重阴影 |

阴影建议：

```css
--shadow-soft: 0 12px 36px rgb(16 42 86 / 0.08);
--shadow-raised: 0 24px 64px rgb(16 42 86 / 0.13);
```

### 4.4 背景与装饰

- 当前 `56px` 网格保留，但只作为 Hero 和少量结构区的低对比纹理。
- 普通 Section 不重复使用网格，避免整站像原型画布。
- 可使用一条柔和径向光、边缘渐隐或窄色带增强层次，不使用霓虹和大面积渐变。
- 装饰不得承载文字、状态或产品事实。

### 4.5 动效

- Hover：按钮轻微上移 `1–2px`，卡片边框和阴影变化。
- Section 进入：`opacity + translateY(8–12px)`，时长 `180–240ms`。
- 流程线与编号：只做轻量显现，不做持续动画。
- `prefers-reduced-motion: reduce` 时关闭位移和自动显现。

## 5. 全局组件换肤

### 5.1 Header

保持现有 `72px` 高度、Wordmark、六项导航和“免费体验”位置不变。

视觉升级：

- 背景从偏暖白调整为纯白或近纯白，增强 SaaS 清爽感。
- Wordmark 主字提升字重，副标题降低对比但保持可读。
- 当前导航继续使用金色下划线，但线条更细、更短。
- 产品 CTA 使用 `8px` 圆角和更稳定的内边距。
- Sticky 状态采用轻阴影与半透明白色，不增加新控件。

### 5.2 PageHero

不改变 `PageHero` 当前网格和内容顺序，只定义三种纯视觉变体：

| 变体 | 使用页面 | 风格 |
| --- | --- | --- |
| `product` | 首页、核心功能 | 冷浅蓝画布、细网格、清晰产品蓝 CTA、SaaS 面板感 |
| `solution` | 团队、关于 | 白色/冷浅蓝画布、较强标题、克制的结构线 |
| `editorial-dark` | 客来宝媒体 | 深蓝画布、冷色关系线、白色标题、绿色咨询 CTA |

约束：

- 当前标题、说明、按钮和 aside 内容完全不变。
- 首页空 `eyebrow` 不应渲染装饰线；不新增 Hero 胶囊标签。
- 没有 aside 的 Hero 不增加产品截图或新面板，只通过背景和排版提升完成度。

### 5.3 Section

保持 Section 数量、顺序、容器宽度和内容不变。

- `ivory`：冷浅蓝背景，适合流程和能力说明。
- `white`：纯白背景，适合正文与密集内容。
- `champagne-mist`：降低黄色倾向，作为轻量强调区。
- `navy`：深蓝重点区，保持高对比反白文字。
- 相邻 Section 通过背景、顶部细线或留白区分，不增加新的分隔组件。

### 5.4 卡片与列表

- 保留当前 Grid、列数和内容顺序。
- 卡片从“细线表格单元”升级为“轻表面层”：柔和圆角、冷灰边框、局部阴影。
- 同一 Grid 内允许通过背景明度和编号位置建立层次，但不得改变卡片尺寸与排列。
- 列表型组件保持列表，不转换成新的 Bento Grid。

### 5.5 CTA、Dialog 与二维码

- CTA 文案、类型和点击行为完全不变。
- 产品按钮维持蓝色，媒体咨询维持绿色。
- 二维码卡增加白边、柔和阴影和更明确的标题层级，不改变二维码资源与尺寸契约。
- Dialog 只换肤，不改变焦点管理、Escape、遮罩和失败路径。

## 6. 页面级视觉方案

### 6.1 首页 `/`：Mindbody × HubSpot

保持当前七个 Section 及全部文案不变。

视觉处理：

- Hero 保持左文案、右问句卡布局；左侧用更强标题尺度与 CTA 层次，右侧卡片用 SaaS 面板样式降低与 H1 的竞争。
- “四类工具”保持四列，使用统一的编号、标题和轻量表面层，借鉴 HubSpot 的模块系统感。
- 五步经营路径保持现有表格/流程结构，通过蓝色阶段线、深蓝起点和浅色状态面提升产品感。
- 四项经营价值保留现有四列，仅增强视觉占位、标题和说明的层次。
- 客来宝媒体摘要保持当前位置，通过深蓝细线和更编辑化的标题处理与产品区区分。
- 最终 CTA 保持深蓝区和二维码布局，强化留白、二维码容器和按钮焦点。

### 6.2 核心功能 `/features`：Mindbody 产品目录风

保持五阶段 Hero、十项工具顺序、每项左右分栏和全部文字不变。

视觉处理：

- Hero 使用产品变体，五阶段标题保持当前内容。
- 五阶段路径保留五列，通过连续进度线和选定式节点增强系统感。
- 十项工具的结构示意统一为同一视觉家族：白色产品框、蓝色标题栏、细线内容区和明确“结构示意”标识。
- 交替左右分栏保持不变，只通过背景带、阴影和分隔间距增加节奏。
- 不将十项工具压缩、合并或改成卡片总览。

### 6.3 团队解决方案 `/team`：HubSpot 解决方案风

保持当前六个 Section、四类瓶颈、四项能力、机制说明和交付保障不变。

视觉处理：

- Hero 使用 `solution` 变体，保持当前标题与 CTA。
- 瓶颈矩阵使用柔和表面与编号系统，降低纯表格感。
- 赋能体系保留当前卡片布局，用统一蓝色结构线连接“问题—能力—机制—交付”的视觉关系。
- 当前引语区使用更大字号、充足留白和细金线，形成页面节奏峰值。
- 交付保障保留当前列数，用步骤编号和浅蓝背景强化可执行感。

### 6.4 客来宝媒体 `/media`：Profound 局部风格

保持当前九个 Section、内容顺序、卡片数量、流程和咨询 CTA 不变。

视觉处理：

- Hero 使用 `editorial-dark`：深蓝背景、低对比网格、白色标题、浅蓝正文和绿色 CTA。
- “为什么需要媒体背书”保持当前卡片布局，改用白色编辑面板和精细编号。
- 长期影响力、核心价值和内容支柱使用冷灰/浅蓝表面与细线关系，减少普通卡片感。
- 当前媒体流程保持节点数量和文字，改用 Profound 式细线轨道与高对比节点。
- 引语使用衬线字体、较大字号和深蓝留白区，形成专业媒体气质。
- 媒体范围与发稿服务保持原结构，用“资料页/出版页”式边框和编号提高可信感。
- 最终企业微信 CTA 继续使用绿色，禁止改成荧光绿或增加 GEO 销售入口。

### 6.5 关于、新闻、案例、联系与政策

不改变当前页面 layout 和内容，仅统一换肤：

- 关于页使用 `solution` Hero、白色事实卡和深蓝合规重点区。
- 新闻和案例保持现有列表/详情结构，使用 HubSpot 式清晰内容层级与编辑留白。
- 联系页保持 K-Link 与客来宝媒体双入口，产品蓝和媒体绿语义不变。
- 政策页保持窄正文布局，只优化标题、链接、表格和目录样式。

---

## 7. 响应式换肤规则

不改变现有断点和组件顺序。

| 视口 | 视觉调整 |
| --- | --- |
| `1440px` | 保持当前 12 列关系，增强 Hero 主次和长页面节奏 |
| `768px` | 保持当前重排逻辑，减小阴影与背景装饰强度 |
| `390px` | 保持单列顺序，H1 控制在 2–3 行，卡片内边距收紧至 `20–24px` |
| `320px` | 保证按钮、长标题、二维码和菜单无裁切；去除非必要装饰 |

移动端重点：

- 不隐藏或删除当前 Hero aside，只降低内边距、字号和视觉重量。
- 主 CTA 保持在标题与说明之后，不移动到新位置。
- 流程和卡片继续按当前单列顺序显示。
- 阴影更轻，圆角保持一致，避免窄屏出现厚重容器堆叠。

## 8. 实施边界与样式组织

### 8.1 代码边界

本方案实施时只应修改：

- 设计 Token 与全局基础样式。
- 现有组件的 class、视觉 variant 和 CSS。
- 页面根节点的视觉主题 class（如需要）。

原则上不修改：

- 页面数据常量、正文、标题、列表和 CTA label。
- JSX 中 Section 的顺序、Grid 内容和组件嵌套关系。
- Provider、Dialog、表单、路由、metadata、结构化数据和服务端代码。
- `/admin`、后台组件、认证与 CMS 操作界面；公开站新增选择器必须以公共 shell、组件或页面 class 为边界。

### 8.2 CSS 收敛建议

当前 `globals.css` 已累积多轮实现。视觉换肤固定使用独立的 `src/app/visual-refresh.css` 后置覆盖层：App Router 在 `src/app/layout.tsx` 中紧随 `globals.css` 导入，Pages Router 在 `src/pages/_app.tsx` 中紧随同一基础样式导入。默认不修改 `globals.css`；只有覆盖层无法安全表达且测试能证明不改变 layout 时，才允许最小原位修正，并在 evidence 中记录原因、影响与回退方式。

推荐层级：

1. `tokens`：颜色、阴影、圆角、间距、字体和动效。
2. `base`：body、标题、链接、focus 和内容正文。
3. `shell`：Header、Footer、容器、CTA、Dialog。
4. `primitives`：PageHero、Section、卡片、流程和二维码。
5. `pages`：home、features、team、media、about 等现有页面选择器。

覆盖层按上述层级分区，不再由实施阶段决定是否拆分。回退验证需临时禁用两个入口的覆盖层 import，运行针对性测试与 build 后恢复；本轮文档不授权改变组件行为或页面结构。

## 9. 验收标准

### 9.1 内容与布局零变化

- 页面路由、Section 数量和模块顺序与当前代码一致。
- 所有用户可见文字逐字保持不变。
- Header、Footer、主导航、CTA、二维码和表单位置关系不变。
- 不新增或删除客户可见功能。

### 9.2 风格目标

- 首页、功能、团队和关于页呈现统一的 Mindbody/HubSpot 式 SaaS 产品感。
- 客来宝媒体页具有 Profound 式深色科技与信息可信感，但仍属于客来宝。
- 全站看起来是正式互联网服务企业官网，不再像结构原型。
- 页面之间有辨识度，同时共享相同字体、颜色、圆角、按钮和组件语言。

### 9.3 交互与响应式

- `320px`、`390px`、`768px`、`1440px` 无横向溢出或文字裁切。
- 移动菜单、两类 Dialog、二维码、表单和所有 CTA 行为无回归。
- 键盘焦点、Escape、200% 缩放和 reduced motion 正确。
- Hover 和进入动画不改变布局尺寸，不造成内容跳动。
- 普通文字对比度不低于 `4.5:1`；大号文字、非文本 UI 边界和 focus-visible 指示不低于 `3:1`。深色反白文字、muted 文本、蓝/绿 CTA、现有 `--champagne` 装饰、disabled、错误/成功和 focus 状态均需记录抽样结果。
- `/admin/login` 与一个受保护后台壳保持既有结构和可用性，不接受公开站覆盖层造成的视觉污染。

### 9.4 页面状态与证据

| 路由族 | 最小状态 | 重点表面与证据 |
| --- | --- | --- |
| `/contact` | 默认双入口、可用表单/未配置降级 | 蓝绿 CTA 语义、表单、二维码与错误状态 |
| `/news`、`/cases` | 列表或空状态；有已发布本地数据时增加代表详情 | 列表/详情标题、链接、日期、正文表面；不得伪造 CMS 数据 |
| `/privacy`、`/terms`、`/disclaimer` | 代表长正文、列表、链接；有表格时检查表格 | 200% 缩放、长 URL、标题层级和正文行宽 |

以上路由状态纳入相同浏览器、DPR、语言/时区、字体、reduced-motion 和四视口 before/after 矩阵。

### 9.5 视觉对照

- 首页以 Mindbody 与 HubSpot 的风格原则为对照，检查产品感、留白、CTA、表面层和模块统一性。
- `/media` 以 Profound 的风格原则为对照，检查深色层次、关系线、专业密度和科技气质。
- 对照只检查视觉语言，不要求布局、内容或组件一一匹配参考网站。
- 实施完成后必须以相同视口对比改造前后截图，并确认没有内容与 layout 漂移。

## 10. 实施顺序

1. 锁定当前页面截图、DOM 顺序与用户可见文案，建立零变化基线。
2. 更新 Token、字体层级、圆角、阴影和背景系统。
3. 换肤 Header、Footer、CTA、Dialog、PageHero 和 Section。
4. 按首页、功能、团队、媒体、关于/内容/政策顺序应用页面视觉样式。
5. 在四个关键视口执行布局、文字、交互和视觉回归。
6. 比较改造前后截图；任何模块位移、文案变化或 CTA 行为变化均视为不通过。

本文只定义视觉升级，不授权修改现有整体 layout、文字内容、产品边界、交互行为或 Production 发布状态。
